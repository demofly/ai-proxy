# Клиентские конфигурации AI Proxy

Образцы содержат вымышленные адреса и реквизиты. Рабочие копии и экспорты
с паролями храните вне репозитория. Ansible разворачивает серверы; адреса
и пароли в клиентские файлы из inventory автоматически не подставляются.

## Какой JSON куда загружать

| Файл | Назначение | Как применить |
| --- | --- | --- |
| [Claude/settings.json](Claude/settings.json) | Фрагмент пользовательских настроек VS Code для Claude Code | Объединить ключи с существующим объектом настроек VS Code |
| [Gemini/settings.json](Gemini/settings.json) | Фрагмент настроек VS Code для Gemini Code Assist | Объединить ключи; заменить `MY_PROJECT_ID` для используемого проекта Google Cloud |
| [FoxyProxy/FoxyProxy.json](FoxyProxy/FoxyProxy.json) | Образец импорта FoxyProxy: один профиль и пять групп правил | Подставить адрес и реквизиты в отдельной копии, импортировать через FoxyProxy |
| [FoxyProxy/domains.json](FoxyProxy/domains.json) | Каталог сервисов, доменов и источников для генератора | Редактировать каталог и запускать `rules.py`; в FoxyProxy этот файл не импортируется |

Файлы проекта — строгий JSON: двойные кавычки, без комментариев и завершающих
запятых. В строках регулярных выражений обратная косая черта удваивается:
`\.com` в редакторе правила записывается как `"\\.com"` внутри JSON.
VS Code допускает JSON с комментариями (JSONC) в пользовательских настройках;
экспорт FoxyProxy и `domains.json` остаются строгим JSON.

## VS Code

Откройте палитру команд (`Ctrl+Shift+P`) → **Preferences: Open User Settings (JSON)**.
Так выбирается файл текущего профиля редактора. Путь
`%APPDATA%/Code/User/settings.json` относится к стандартному профилю Windows;
у дополнительных профилей расположение отличается.

Переносите **ключи** из образцов внутрь уже существующих внешних `{}`.
Обновляйте существующий ключ вместо добавления второго одноимённого.
Так сохраняются остальные настройки редактора. Файл
`Clients/Claude/settings.json` предназначен для VS Code, а не для
`.claude/settings.json`; образец Gemini также не является настройками Gemini CLI.

### Claude Code

`claudeCode.environmentVariables` — массив объектов `name` / `value`.
Он передаёт `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` запускаемому Claude Code.
Если массив уже есть, дополните его или обновите существующие записи.
После изменения перезапустите сеанс расширения.

### Gemini Code Assist

`http.proxy` задаёт адрес прокси VS Code; тот же параметр используется для
обращений к HTTPS-сайтам. Отдельного ключа `https.proxy` в образце нет.
`geminicodeassist.project` относится к проекту Google Cloud; выбирайте значение
для используемого варианта Code Assist. Текущие требования установки и аккаунта
описаны в [руководстве Google](https://docs.cloud.google.com/gemini/docs/codeassist/set-up-gemini),
параметры прокси — в [сетевых настройках Google](https://docs.cloud.google.com/gemini/docs/codeassist/network-access).

Для обоих образцов замените `user`, `password`, `proxy.example.com` и порт
полученными от администратора значениями. В URL символы пароля вроде `@`, `:`
и `/` кодируются процентами. Тип подключения к прокси определяет схема URL:
`http://proxy.example.com:443` — HTTP-прокси на порту 443. Номер порта сам по себе
не включает HTTPS-прокси. TLS целевого сайта устанавливается внутри CONNECT.

Настройки расширений зависят от их сетевой реализации; браузерный FoxyProxy
на них не действует. Область действия параметров VS Code описана в
[документации редактора](https://code.visualstudio.com/docs/configure/settings).

## Firefox и FoxyProxy

Выборочная маршрутизация включается режимом **по шаблонам** (`mode: "pattern"`).
Группы: `AI`, `Dev`, `Design`, `Social`, `Auth`. Сохранены исходные исключения
пользователя; добавления включены только при наличии в выбранной копии реестра РКН.
[Версия снимка и основания включения](FoxyProxy/registry-review.md) указаны отдельно.
Неподходящие URL идут напрямую. Серверный белый список Squid задаётся отдельно.

Для первой настройки отредактируйте отдельную копию `FoxyProxy.json`:
`hostname` — имя узла без схемы и порта, `port` — строка, `username` и `password` —
отдельные поля. В этих двух полях используется сам пароль, без URL-кодирования.
Импортируйте копию через настройки FoxyProxy → **Import**.

Для действующей настройки экспортируйте её целиком и обновите правила:

```powershell
python Clients/FoxyProxy/rules.py --merge C:/Private/foxy-before.json --output C:/Private/foxy-updated.json
```

Команда выполняется из корня репозитория, требует Python 3.10+ и новый выходной
файл вне репозитория. Она обновляет каталог правил в каждом профиле и сохраняет
его подключение, реквизиты, активность и остальные настройки. Затем импортируйте
результат и проверьте режим **по шаблонам**.

Поля JSON, объединение правил нескольких профилей, проверка и восстановление
описаны в [руководстве FoxyProxy](FoxyProxy/README.md).

## PowerShell и командные утилиты

Для текущей сессии и запущенных из неё приложений:

```powershell
$env:HTTP_PROXY = "http://user:password@proxy.example.com:443"
$env:HTTPS_PROXY = "http://user:password@proxy.example.com:443"
$env:NO_PROXY = "localhost,127.0.0.1,::1,.local"
```

Для постоянной настройки пользователя служит
[register-vars.ps1](PowerShell/register-vars.ps1), для удаления —
[unregister-vars.ps1](PowerShell/unregister-vars.ps1). Перед запуском замените
реквизиты в приватной копии сценария. Эти сценарии изменяют пользовательские
переменные Windows; уже работающая оболочка не получает их автоматически.
Перезапустите оболочку и IDE, а для немедленного изменения текущего процесса
задайте `$env:…`, как выше. Если родительское приложение продолжает передавать
старое окружение, завершите сеанс Windows и войдите снова.

Альтернатива — добавить строки `$env:…` в файл, путь к которому показывает
`$PROFILE`. Они будут выполняться при запуске PowerShell. Для удаления из
текущей сессии используйте `Remove-Item Env:HTTP_PROXY, Env:HTTPS_PROXY, Env:NO_PROXY`.

`NO_PROXY` относится к приложениям, которые его поддерживают. Исключения
FoxyProxy задаются в самом расширении и не берутся из этой переменной.
