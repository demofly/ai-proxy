# 4. Учётные записи

## Где хранятся

Записи лежат в файле рядом с инвентарём на управляющей машине и раздаются на узлы
уровня доступа при развёртывании. Пароли хранятся хешами; восстановить пароль из хеша
нельзя — забытый пароль перевыпускается.

Инвентарь при заведении записи **не правится**: перечня учётных записей в нём нет.

## Завести запись

```bash
htpasswd -B -C 12 -bn пользователь пароль >> passwd
ansible-playbook -i inventory.yml playbook.yml -t passwd
```

Первая команда печатает строку, которая дописывается в файл:

<!-- [AIV: date=2026-08-31; method=stand-wsl2-incus; result=not-applicable; note=формат строки, значимая часть заменена заполнителем] -->
```text
demo:$2y$12$<двадцать два символа соли><тридцать один символ свёртки>
```
<!-- [/AIV] -->

Второй командой файл раздаётся на узлы и служба перечитывает его без разрыва
действующих соединений.

**Одна запись на пользователя.** Дописывание второй строки с тем же именем не заменяет
прежнюю: служба берёт первую совпавшую и остальные не смотрит, поэтому смена пароля
дописыванием даёт отказ проверки подлинности при внешне верных реквизитах. Прежняя
строка удаляется до добавления новой.

## Удалить запись

Строка удаляется из файла, затем выполняется та же раздача. Действующие соединения
удалённого пользователя при этом **не рвутся**: проверка подлинности выполняется при
установлении соединения, а не постоянно. Чтобы прервать их немедленно, службу
перезапускают — ценой разрыва соединений всех пользователей узла.

## Сменить пароль

Строка заменяется новой с тем же именем, далее раздача. Пользователю нужно обновить
реквизиты в своём окружении — раздача конфигураций рабочим местам выполняется вручную.

## Группы пользователей и пулы

### Как устроено

Через какие узлы второго уровня идут обращения пользователя, задают два параметра
инвентаря.

- **Группа** — именованный перечень учётных записей из файла паролей. Особая группа
  `all` означает всех пользователей файла паролей и не объявляется.
- **Пул** — связь групп с набором узлов второго уровня: в пул входят пользователи
  перечисленных групп, а обращения идут через перечисленные узлы.

Пользователь может входить в несколько групп, а группа — в несколько пулов. Набор узлов
пользователя — **объединение** узлов всех пулов, в которые входит хотя бы одна его
группа. Внутри набора узел выбирается по имени учётной записи, поэтому пользователь
устойчиво привязан к одному узлу набора.

Пул действует, только когда в нём есть и пользователи, и узлы. Пул без того или другого
никого не направляет. Если набор пользователя пуст, его обращения получают отказ
с кодом 403 даже при верном пароле. Так происходит, когда пользователь не входит ни в один
пул либо все его пулы без узлов. Отказ действует и при разрешённом запасном прямом
выходе. Обращение без реквизитов по-прежнему получает отказ проверки подлинности
с кодом 407, если действует хотя бы один пул. Без единого действующего пула узел доступа
отклоняет все обращения с кодом 403 ещё до проверки подлинности, в том числе обращения
без реквизитов.

Пулы общие для всех узлов доступа: каждый узел доступа направляет пользователя в один
и тот же набор. Отдельного набора для одного узла доступа нет.

**Умолчание.** Без параметров действуют два пула:

- `default` — все пользователи через все узлы второго уровня;
- `reserve` — пустой и по пользователям, и по узлам.

Умолчание повторяет прежнее поведение. Заданный в инвентаре перечень пулов **заменяет
его целиком**: если пул с группой `all` в перечень не включён, пользователи вне
объявленных групп получат отказ 403.

### Отнести пользователя к группе и группу к пулу

1. Убедитесь, что запись пользователя есть в файле паролей (раздел «Завести запись»).
   Имя из группы без записи в файле останавливает развёртывание узлов доступа.
2. Допишите имя пользователя в группу параметра `proxy_user_groups` либо заведите
   новую группу.
3. Укажите группу в поле `groups` нужного пула параметра `proxy_pools`. В поле
   `upstreams` укажите `all` (все узлы второго уровня из инвентаря) либо список имён
   узлов.
4. Примените конфигурацию прокси-сервера полным прогоном развёртывания:

   ```bash
   ansible-playbook -i inventory.yml playbook.yml --limit access_proxies
   ```

   Раздачи файла паролей (`-t passwd`) недостаточно: состав групп и пулов входит
   в конфигурацию прокси-сервера, а не в файл паролей.

Правила имён групп, пользователей и пулов — в [разделе 9](09-parameters.md).

### Пример

```yaml
proxy_user_groups:
  team-a: [alice, bob]
  team-b: [bob, carol]
proxy_pools:
  - {name: alpha, groups: [team-a], upstreams: [upstream-01]}
  - {name: beta, groups: [team-b], upstreams: [upstream-02]}
```

Пусть в файле паролей есть записи `alice`, `bob`, `carol` и `dave`. Тогда:

| Пользователь | Набор узлов второго уровня |
|---|---|
| `alice` | `upstream-01` (пул `alpha`) |
| `bob` | `upstream-01` и `upstream-02`: объединение пулов `alpha` и `beta` |
| `carol` | `upstream-02` (пул `beta`) |
| `dave` | пуст: ни в одной группе нет, отказ 403 |

Чтобы `dave` и все будущие учётные записи получали хотя бы один узел, добавьте пул
с группой `all`, например `{name: everyone, groups: [all], upstreams: [upstream-01]}`.

### Проверить, что получится

Развёртывание проверяет группы и пулы до первого изменения узла, причём при любом
наборе тегов, в том числе при `-t passwd` и `-t nginx`. Если перечень неверен,
развёртывание узлов доступа останавливается с сообщением, и их конфигурация и службы
не меняются. Узлы второго уровня прогон продолжает. Примеры причин:

- неизвестная группа или неизвестный узел второго уровня;
- повтор имени;
- пользователь группы без записи в файле паролей.

Разбор сообщений — в [разделе 8](08-troubleshooting.md).

В выводе развёртывания для каждого узла доступа печатается состав пулов. Для примера
выше строка пула `alpha` выглядит так: `Пул alpha: 2 польз., upstream: upstream-01`.
Пул с группой `all` показан словами «все пользователи», у пула без узлов вместо
перечня стоит «нет».

После развёртывания проверьте отказ пользователю вне пулов:

```bash
# Пользователь вне пулов получает 403, а не 407: пароль принят, маршрута нет
curl -sI --max-time 20 -x http://203.0.113.10:3128 -U dave:пароль http://example.com | head -1
```

Ожидаемая первая строка ответа — `HTTP/1.1 403 Forbidden`. Узел второго уровня, через
который прошло обращение пользователя из пула, записан в журнале обращений рядом
с именем учётной записи.

## Что видно в журнале

Имя учётной записи попадает в журнал обращений: по нему видно, кто и к какому сервису
обращался. Пароль и содержимое обмена в журнал не попадают никогда.

## Ограничение

Доступ ограничивают проверка подлинности, пулы и списки разрешённых сервисов. При
умолчании пулов и без списков подтвердивший подлинность получает доступ ко всем сервисам
через все узлы второго уровня. Пустой список означает «сужения нет». Это заданное
поведение, а не упущение.
