# 4. Учётные записи

## Где хранятся

Записи лежат в файле рядом с инвентарём на управляющей машине и раздаются на узлы
уровня доступа при развёртывании. Пароли хранятся хешами; восстановить пароль из хеша
нельзя — забытый пароль перевыпускается.

Инвентарь при заведении записи **не правится**: перечня учётных записей в нём нет.

## Завести запись

```bash
htpasswd -B -C 12 -bn пользователь пароль >> passwd
ansible-playbook -i inventory.yml playbook.yml -t passwd
```

Первая команда печатает строку, которая дописывается в файл:

<!-- [AIV: date=2026-08-31; method=stand-wsl2-incus; result=not-applicable; note=формат строки, значимая часть заменена заполнителем] -->
```text
demo:$2y$12$<двадцать два символа соли><тридцать один символ свёртки>
```
<!-- [/AIV] -->

Второй командой файл раздаётся на узлы и служба перечитывает его без разрыва
действующих соединений.

**Одна запись на пользователя.** Дописывание второй строки с тем же именем не заменяет
прежнюю: служба берёт первую совпавшую и остальные не смотрит, поэтому смена пароля
дописыванием даёт отказ проверки подлинности при внешне верных реквизитах. Прежняя
строка удаляется до добавления новой.

## Удалить запись

Строка удаляется из файла, затем выполняется та же раздача. Действующие соединения
удалённого пользователя при этом **не рвутся**: проверка подлинности выполняется при
установлении соединения, а не постоянно. Чтобы прервать их немедленно, службу
перезапускают — ценой разрыва соединений всех пользователей узла.

## Сменить пароль

Строка заменяется новой с тем же именем, далее раздача. Пользователю нужно обновить
реквизиты в своём окружении — раздача конфигураций рабочим местам выполняется вручную.

## Что видно в журнале

Имя учётной записи попадает в журнал обращений: по нему видно, кто и к какому сервису
обращался. Пароль и содержимое обмена в журнал не попадают никогда.

## Ограничение

Проверка подлинности — единственное, что ограничивает доступ, если не заданы списки
разрешённых сервисов. Пустой список означает «сужения нет»: подтвердивший подлинность
получает доступ ко всем сервисам. Это заданное поведение, а не упущение.
