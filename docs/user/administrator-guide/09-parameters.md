# 9. Параметры настройки

Параметры задаются в инвентаре. Приведены умолчания; значения, при которых служба
ведёт себя иначе, отмечены в описании.

## Состав узла

| Параметр | Назначение | Умолчание |
|---|---|---|
| `proxy_role` | Уровень узла: доступа либо зарубежный | задаётся на узел |
| `enable_auth` | Проверка подлинности обращений | включена на уровне доступа |
| `enable_logging` | Журнал обращений | включён на уровне доступа, выключен на зарубежном |
| `enable_caching` | Кеширование ответов | включено на уровне доступа |
| `crowdsec_enabled` | Обнаружение вторжений | включено |
| `mtproxy_enabled` | Служба доступа к обмену сообщениями | включена на зарубежном уровне |
| `enable_keepalived` | Переключение виртуального адреса | выключено |

## Доступ

| Параметр | Назначение | Умолчание |
|---|---|---|
| `proxy_port` | Внешний порт: за общим nginx только 443; для прямого Squid настраивается | 443 в образце inventory |
| `behind_nginx` | Squid на loopback за SNI router; upstream поддерживает этот режим и без MTProxy | автоопределение, true в образце |
| `squid_local_port` | Loopback Squid, SNI fallback и назначения TLS-терминаторов | 3128 |
| `squid_mgmt_port` | Отдельный loopback HTTP manager, только для управления и healthcheck | 3129 |
| `allowed_domains` | Список разрешённых сервисов | не задан: сужения нет |
| `allowed_domain_patterns` | Список разрешённых сервисов по образцу имени | не задан |
| `allow_direct_fallback` | Запасной прямой выход при недоступности всех узлов второго уровня из набора пользователя. Во включённом режиме защищённые обращения (CONNECT) тоже идут через узлы второго уровня, а напрямую — только когда живых узлов набора нет. Пользователь вне пулов получает отказ 403 и в этом режиме | выключен: прямой выход раскрыл бы целевому сервису адрес узла в стране |

## Группы пользователей и пулы

Порядок настройки и пример — в [разделе 4](04-accounts.md). Параметры общие для всех
узлов доступа: переопределения на отдельный узел нет.

| Параметр | Назначение | Умолчание |
|---|---|---|
| `proxy_user_groups` | Отображение «имя группы → список имён пользователей из файла паролей» | пусто |
| `proxy_pools` | Список пулов: какие группы через какие узлы второго уровня. Заданный список заменяет умолчание целиком | пул `default` (группа `all`, все узлы) и пустой пул `reserve` |

Пул задаётся отображением ровно из трёх ключей:

| Ключ | Значение |
|---|---|
| `name` | Имя пула, уникальное в списке |
| `groups` | Список имён групп из `proxy_user_groups` без повторов. Особая группа `all` означает всех пользователей файла паролей |
| `upstreams` | `all` — все узлы группы upstreams инвентаря на момент развёртывания. Либо список имён узлов из этой группы без повторов |

Набор узлов пользователя — объединение узлов всех пулов, в которые входит его группа.
Пустой набор даёт отказ 403. Пул без пользователей либо без узлов никого не направляет.

Правила имён:

- группа — латинские буквы, цифры, `_`, `.`, `-`, первый знак буква или цифра,
  не длиннее 64 знаков. Имя `all` зарезервировано;
- пользователь — латинские буквы, цифры, `.`, `_`, `@`, `+`, `-`, первый знак буква
  или цифра, не длиннее 128 знаков. Имя `REQUIRED` запрещено;
- пул — строчные латинские буквы, цифры, `_`, `-`, первый знак строчная буква,
  не длиннее 32 знаков.

Имя, которое YAML читает как число либо булево значение (`1001`, `007`, `no`),
берётся в кавычки: иначе развёртывание остановится.

**Упразднённый параметр.** `squid_upstream_hosts` — прежний перечень узлов второго уровня
для одного узла доступа. Его заменили пулы. Если параметр задан, развёртывание
останавливается до изменения служб с указанием перенести набор узлов в `proxy_pools`.

## Тайминги

| Параметр | Что ограничивает | Умолчание |
|---|---|---|
| `read_timeout` | Простой соединения без передачи данных | 1 час |
| `client_lifetime` | Жизнь соединения целиком | 1 сутки |
| `client_idle_pconn_timeout` | Удержание неиспользуемого постоянного соединения | 60 секунд |

Предел жизни обязан быть строго больше предела простоя: иначе рвать соединение будет он,
и активный обмен погибнет наравне с бездействующим.

## Сроки хранения имён

| Параметр | Назначение | Умолчание |
|---|---|---|
| `squid_positive_dns_ttl` | Хранение разрешённого имени в кеше прокси-сервера | 6 часов |
| `squid_negative_dns_ttl` | То же для отрицательных ответов | 30 секунд |

Резолвер узла собственных сроков не навязывает: запись живёт столько, сколько объявил
владелец зоны.

## Шифрование участка между узлами

| Параметр | Назначение | Умолчание |
|---|---|---|
| `squid_transit_tls` | Шифрование участка между уровнями | включено |
| `squid_tls_sni` | Опознавательное имя участка; в системе имён разрешаться не обязано | задаётся |
| `squid_tls_term_port` | Порт снятия шифрования на зарубежном узле за маршрутизатором | 4444 |

## Журналы

| Параметр | Назначение | Умолчание |
|---|---|---|
| `sni_router_access_log` | Путь журнала маршрутизации | `/var/log/nginx/sni-router.log` |
| `sni_router_log_buffered` | Буферизовать запись журнала маршрутизации | включена |
| `squid_log_rotate_period` | Период ротации | ежедневно |
| `squid_log_rotate_keep` | Глубина хранения | 14 файлов |

Перед изменением служб проверяются диапазоны портов и отсутствие конфликтов
между включёнными слушателями. Внешний 443 закреплён за общим SNI router;
локальные порты настраиваются согласованно. Полный перечень настроек:
[inventory.yml.sample](../../../Servers/deploy/inventory.yml.sample).

## Память и пределы

| Параметр | Назначение | Умолчание |
|---|---|---|
| `mem_reserve_share` | Доля узла, оставляемая ядру при одиночном размещении | 0.25 |
| `mem_share_when_shared` | Дополнительная доля узла; общий предел и резерв соседей действуют всегда | 1.0 |
| `proxy_memory_budget_mb` | Необязательный меньший потолок всего ai-proxy, МиБ; включая общие nginx/CrowdSec. Не может поднять автоматический бюджет | автоматически min(max(RAM/3, сумма минимумов включённых служб), 1000000000 байт) |
| `proxy_memory_limits` | Частичные фиксированные пределы служб в МиБ; остальные распределяются автоматически, минимумы и сумма проверяются до деплоя | автоматическое распределение со встроенными минимумами служб |
| `proxy_max_connections` | Верхний предел совокупных сессий локальных TLS-реле ai-proxy; фактический ограничен также памятью | 96 |
| `mtproxy_max_connections` | Верхний предел сессий mtg; фактический ограничен памятью и FD, без привязки к IP | 64; в примере inventory 100 |
| `nginx_worker_connections` | Слотов на worker: учитываются оба конца и оба nginx-hop | 512 |
| `squid_mgmt_port` | Порт снятия показателей на петлевом адресе; снаружи недостижим | 3129 |
| `squid_min_version` | Минимальная версия прокси-сервера | 5.7 |

Ниже минимально допустимой памяти отдельные службы не ужимаются. Если их сумма
превышает треть RAM, бюджет повышается до этой суммы; явные пределы отдельных
служб также сохраняются. Потолок 1 ГБ, явный общий предел inventory, резерв ОС
и резерв соседей остаются жёсткими: при невозможности соблюсти их деплоймент
останавливается до установки пакетов. Автоматического отключения служб нет.

## Разрешение имён

| Параметр | Назначение | Умолчание |
|---|---|---|
| `dns_servers` | Публичные серверы имён для зарубежного узла | три независимых адреса |
| `dns_extra_clients` | Кому ещё разрешено обращаться к резолверу | никому сверх узлов уровня доступа |
| `dns_resolver_dnssec` | Проверка подписей записей | включена |
