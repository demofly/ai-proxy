# 5. Обслуживание и обновление

## Обновление служб

Развёртывание переводит службы узла на новые версии из репозитория дистрибутива при
каждом прогоне. Признак в инвентаре позволяет заморозить версии: тогда прогон сводит
только конфигурацию.

**Последствие, которое признак не устраняет:** обновление пакета перезапускает службу
силами самого пакета, до и помимо средств развёртывания. Клиентские соединения при этом
рвутся. Поэтому:

- узлы обновляются **по одному**: пара узлов уровня доступа не уходит в перезапуск разом;
- момент перезапуска приходится на прогон развёртывания, то есть известен заранее,
  в отличие от фонового обновления по расписанию.

Одно исключение — служба межсетевого экрана: её остановка сбрасывает правила узла
целиком, включая правила соседних служб. Она обновляется вручную в плановое окно.

## Что делать перед обновлением

1. Предупредить пользователей: соединения прервутся и потребуют переустановления.
2. Убедиться, что второй узел пары обслуживает обращения, если пара есть.
3. Прогнать развёртывание и дождаться сообщения о завершении.

## Проверка состояния

```bash
systemctl status squid unbound nginx                          # состояние служб узла
squid -k parse                                                # разбор конфигурации без применения
squidclient -h 127.0.0.1 -p 3129 mgr:info                     # обращения, соединения, попадания в кеш
squidclient -h 127.0.0.1 -p 3129 mgr:server_list              # состояние узлов второго уровня
journalctl -u squid --since -1h                               # события службы за час
```

Значение `Status: Down` означает, что узел признан недоступным после двух неудачных
попыток подряд. Пока хотя бы один узел жив, обслуживание продолжается; когда недоступны
все, обращения завершаются отказом — прямой выход запрещён.

**Порт управления указывается обязательно.** Рабочий порт для снятия показателей
непригоден: при работе за маршрутизатором он требует служебного заголовка, а при
шифровании участка принимает только защищённые соединения. Порт управления слушает
петлевой адрес и снаружи недостижим; его номер задаётся параметром инвентаря.

Утилита снятия показателей ставится развёртыванием: в поставку прокси-сервера она
не входит.

## Резервное копирование

Копированию подлежат два файла с управляющей машины: инвентарь и файл учётных записей.
Всё остальное состояние узлов воспроизводится развёртыванием.

Материал шифрования участка между узлами лежит в отдельном каталоге рядом с инвентарём
и тоже подлежит копированию: при его утрате участок перестанет устанавливаться, пока
не будет выпущен и роздан заново.
