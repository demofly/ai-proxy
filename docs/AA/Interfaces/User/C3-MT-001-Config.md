# C3-MT-001-Config — приём обращений MTProxy

|---|---|
| **Компонент** | [C3-MT-001](../../C3/C3-MT-001.md) — MTProxy |

| **Требования** | [C2-FR-006](../../C2/C2-FR-006.md) |

## Точка подключения

| Узел | Что слушает | Как попадает обращение |
|---|---|---|
| Уровня доступа | `127.0.0.1:{mtproxy_relay_port}` | Маршрутизатор направляет по имени `mtproxy_fake_tls_domain`, затем ретрансляция на зарубежный узел |
| Зарубежный | `127.0.0.1:{mtproxy_tls_port}` — терминатор, за ним демон на `{mtproxy_local_port}` | Маршрутизатор направляет по `mtproxy_fake_tls_domain`; `mtproxy_hostname` — необязательное дополнительное имя |

Наружу оба узла принимают только на 443: собственных внешних портов у MTProxy нет.

## Реквизиты потребителя

Секрет в шестнадцатеричной записи (`mtproxy_secret`) общий для включённых upstream.
При пустом значении сначала переиспользуется существующий общий секрет узлов,
затем, если его нигде нет, однократно генерируется общий секрет на контроллере.
Резерв энтропии — `secrets/mtproxy-entropy`; конфликтующие секреты не ротируются автоматически. Имя маскировки
(`mtproxy_fake_tls_domain`) обязано совпадать у потребителя и в карте имён узла: при
расхождении соединение уйдёт бэкенду по умолчанию, где протокол не разбирается.

## Ограничение

`mtproxy_max_connections` — общий верхний предел подключений mtg, не на IP.
Эффективное значение дополнительно ограничивается бюджетом памяти и FD.
Исходный IP клиента намеренно не передаётся в mtg через PROXY protocol.
Домен fake-TLS по умолчанию — `max.ru`, одинаковый в секрете и маршруте реле.
