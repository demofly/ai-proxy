## Журнал обращений прокси

| Свойство | Значение |
|---|---|
| Файл | `/var/log/squid/access.log` |
| Условие | `enable_logging` включён; на зарубежном уровне выключен намеренно |
| Состав | Время, длительность, адрес клиента, код результата и HTTP-статус, объём, метод, цель, имя потребителя, код иерархии и адрес вышестоящего узла |
| Ротация | `/etc/logrotate.d/squid-aiproxy`: период `squid_log_rotate_period`, глубина `squid_log_rotate_keep`, усечение на месте |

## Журнал маршрутизации

| Свойство | Значение |
|---|---|
| Файл | `sni_router_access_log`, по умолчанию `/var/log/nginx/sni-router.log` |
| Условие | Узел работает за маршрутизатором (`nginx_on_443`) |
| Состав | Адрес клиента, время, запрошенное имя SNI в позиции цели запроса, код завершения сессии, объём, адрес назначения в позиции источника перехода |
| Буферизация | 32 КБ с выгрузкой раз в 5 секунд (`sni_router_log_buffered`), чтобы запись не входила в путь каждого соединения |

Вид записи подчинён требованию разбора ([C3-CS-001-Config](C3-CS-001-Config.md)):
поля потокового режима в шаблоне разбора отсутствуют, поэтому имя и адрес назначения
занимают позиции полей HTTP-журнала.

## Что в журналы не попадает

Содержимое обмена: оно защищено сквозным шифрованием и прокси недоступно. Записывается
факт обращения, его адресат и объём — но не то, что передано.

**Цена ведения журнала маршрутизации** названа прямо: узел хранит след того, к каким
сервисам обращались, что ослабляет неразличимость обращений — свойство, ради которого
построена двухуровневая цепочка.
