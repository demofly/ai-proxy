# Interfaces — спецификации интерфейсов

**Последняя правка AI:** 2026-08-30T15:37:22Z

Корпус контрактов: что компонент принимает и отдаёт, в каком виде и на каких условиях.
Устройство самого компонента описывает его карточка C3 — здесь только граница, через
которую он взаимодействует с чем-то за своими пределами.

Разделение по классу (одна поддиректория на интерфейс, пересечений нет):

| Класс | Что относится | Директория |
|---|---|---|
| Integration | Обмен с внешними системами и между узлами продукта: прокси-протокол, цепочка уровней, обращения к целевым сервисам | `Integration/` |
| User | Поверхность, наблюдаемая и настраиваемая оператором: конфигурации служб, журналы, командные утилиты | `User/` |
| Internal | Библиотеки и межпроцессный обмен внутри одного узла | не применяется: собственных библиотек продукт не поставляет, а обмен между службами узла идёт через сетевые интерфейсы, описанные в двух классах выше |

## Правила корпуса

1. Контракт описывается **со стороны потребителя**: что он обязан прислать и что получит
   в ответ, включая поведение при отказе. Внутреннее устройство — в карточке компонента.
2. Значения берутся из кода и конфигураций; при расхождении ведёт код.
3. Изменение, ломающее совместимость (удаление, переименование, смена типа), требует
   новой мажорной версии интерфейса и срока вывода прежней из обращения.
