## Две ветки приёма

Выбор делает обращающаяся сторона по устройству принимающего узла.

| Устройство принимающего узла | Точка подключения | Кто снимает шифрование |
|---|---|---|
| MTProxy выключен | `{ansible_host}:{squid_port}` | Сам прокси (`https_port` с сертификатом участка) |
| MTProxy включён | `{ansible_host}:443`, имя участка в SNI | Терминатор за маршрутизатором, затем поток идёт прокси с восстановлением адреса клиента |

При выключенном `squid_transit_tls` обе ветки принимают открытым текстом; тогда
наблюдателю между узлами виден заголовок CONNECT, то есть имя целевого сервиса.

## Проверка сторон

| Сторона | Чем проверяется |
|---|---|
| Принимающая | Обращающаяся сверяет сертификат участка: `tls-no-default-ca` отсекает системные удостоверяющие центры, `tls-cafile` задаёт единственный доверенный сертификат, `tls-domain` — проверяемое имя |
| Обращающаяся | Принимающая сверяет адрес источника: разрешены только адреса узлов уровня доступа, на сетевом уровне и в списке доступа службы |

Проверка подлинности потребителя на этом участке **не выполняется** повторно: она уже
выполнена на уровне доступа, а имя потребителя передаётся дальше только как основание
выбора узла.

## Что делает принимающая сторона

1. Снимает признаки прохождения через прокси и пересылаемый адрес клиента.
2. Подменяет строку браузера постоянным значением, одинаковым на обоих уровнях.
3. Открывает соединение с целевым сервисом от своего адреса.

Целевой сервис видит обращение от зарубежного узла; адрес потребителя и адрес узла
в РФ ему недоступны.

## Отказы

| Поведение | Причина |
|---|---|
| Соединение отвергается | Адрес источника не в списке разрешённых |
| Рукопожатие не проходит | Сертификат участка не совпадает с доверенным у обращающейся стороны либо имя не то |
| Узел помечается мёртвым | Две неудачные попытки подряд; проверяется снова через 15 секунд |
