# C2-NF-003 — Производительность (SMP, memory tuning)

**Последняя правка AI:** 2026-08-29T04:53:52Z

## Ссылки

- Родительские требования C1: [C1-BC-004](../C1/C1-BC-004.md)
- Дочерние требования C3: [C3-SA-001](../C3/C3-SA-001.md), [C3-SU-001](../C3/C3-SU-001.md), [C3-DN-001](../C3/C3-DN-001.md)
- Архитектурные решения: [ADR-000002](../ADR/ADR-000002.md) — прокси-движок, [ADR-000008](../ADR/ADR-000008.md) — бюджет памяти узла, [ADR-000009](../ADR/ADR-000009.md) — кеширующий резолвер

## Описание

Система оптимизирует производительность проксирования через настройку SMP (Symmetric Multi-Processing) Squid, динамическое управление памятью, увеличение лимитов файловых дескрипторов и тюнинг сетевых параметров ядра. Оптимизация особенно важна для upstream-уровня, обслуживающего долгоживущие соединения к AI API.

### 1. SMP Workers (Squid)

Squid поддерживает многопоточную обработку через SMP workers:

| Параметр | Access-уровень | Upstream-уровень |
|---|---|---|
| `workers` | `ansible_processor_vcpus` | `ansible_processor_vcpus` |

Оба шаблона выпускают директиву одинаково — по числу виртуальных процессоров узла и только при значении больше единицы. На узле с одним процессором директива не выпускается вовсе, и Squid работает единственным процессом.

Разделение по уровням отсутствует: правило одно для обоих. При этом нагрузка уровней различна — access обслуживает клиентов инженерной команды, upstream держит долгоживущие туннели ко всем AI API.

### 2. Динамическое выделение памяти

| Параметр | Формула | Описание |
|---|---|---|
| `cache_mem` | 25% предела памяти службы | Кеш объектов в памяти в пределах бюджета узла |
| `cache_dir` size | 100 MB, значение задано в шаблоне | Дисковый кеш access-узла; от объёма памяти узла не зависит |
| `maximum_object_size_in_memory` | 512 KB | Максимальный размер объекта в RAM |

Формулы адаптируют конфигурацию к ресурсам конкретного сервера без ручной настройки.

### 3. Лимиты файловых дескрипторов

| Параметр | Значение | Описание |
|---|---|---|
| `fd_limit` | `max(vcpus × 4096, 65535)` | Расчётный лимит дескрипторов, общий для обоих уровней |
| `max_filedescriptors` | `{{ fd_limit }}` | Тот же предел, выпускаемый директивой Squid. Прежде задавался только через systemd и limits.d, а сам Squid брал значение из окружения — действующий предел не был виден в конфигурации службы, и расхождение с пределом узла обнаруживалось лишь под нагрузкой |
| systemd `LimitNOFILE` | `fd_limit` в `squid.service.d/limits.conf` | Лимит процесса Squid |
| `/etc/security/limits.d/99-proxy.conf` | `* soft/hard nofile` = `fd_limit` | Лимит на уровне пользователя |

### 4. Таймауты для AI API

| Параметр | Значение | Обоснование |
|---|---|---|
| `read_timeout` | 1 час: и умолчание шаблона, и значение образца инвентори | Предел ПРОСТОЯ, а не общей длительности: обращение живёт сколько угодно, пока по нему идут данные |
| `connect_timeout` | 15 секунд | Время установления соединения с целевым узлом |
| `request_timeout` | 30 секунд | Ожидание запроса от клиента после установления соединения |
| `persistent_request_timeout` | 60 секунд | Ожидание следующего запроса в неразрывном соединении |
| `dns_timeout` | 15 секунд | Ожидание ответа резолвера |
| `connect-timeout` пира | 5 секунд | Быстрое обнаружение недоступного upstream (параметр `cache_peer`) |
| `dead_peer_timeout` | 15 секунд | Период повторной проверки мёртвого пира |

### 5. Sysctl tuning

| Параметр | Значение | Описание |
|---|---|---|
| `net.core.somaxconn` | 65535 | Максимальная очередь подключений |
| `net.netfilter.nf_conntrack_max` | 262144 | Таблица conntrack |
| `net.ipv4.tcp_rmem` | 4096 87380 16777216 | Буферы чтения TCP |
| `net.ipv4.tcp_wmem` | 4096 65536 16777216 | Буферы записи TCP |
| `net.ipv4.ip_local_port_range` | 1024 65535 | Диапазон эфемерных портов |

### Количественные целевые значения

| Метрика | Целевое значение | Метод измерения |
|---|---|---|
| Утилизация CPU (upstream) | < 80% на ядро | top / vmstat |
| Утилизация RAM | < 90% | free -m |
| Время установления CONNECT-туннеля | < 2 секунды | Замер curl --proxy (без TLS handshake с target) |
Доступность утилиты `squidclient`, названной ниже способом измерения, на узлах не подтверждена: отдельно она не устанавливается, а входит ли в пакет squid используемого дистрибутива — не проверено ([Ideas.md](../Ideas.md), GAP-106).

| Concurrent connections (upstream) | ≥ 1000 на worker | squidclient mgr:info |
| File descriptors in use | < 80% от `fd_limit` | squidclient mgr:info |

## Критерии приёмки

| # | Критерий | Метрика / Способ проверки | Целевое значение |
|---|----------|---------------------------|------------------|
| 1 | Число рабочих процессов равно числу виртуальных процессоров | `grep workers /etc/squid/squid.conf` | Значение равно `ansible_processor_vcpus`; при единственном процессоре директива отсутствует |
| 2 | `cache_mem` соответствует бюджету | `grep cache_mem /etc/squid/squid.conf` | 25 % предела памяти службы Squid, а не доли памяти узла |
| 3 | Лимит дескрипторов ≥ 65535 и виден в конфигурации службы | `systemctl show squid -p LimitNOFILE` и `grep max_filedescriptors /etc/squid/squid.conf` | ≥ 65535 в обоих местах, значения совпадают |
| 4 | Предел простоя туннеля = 1 час | `grep read_timeout /etc/squid/squid.conf` | `1 hour` |
| 5 | sysctl значения применены | sysctl net.core.somaxconn | 65535 |

## Доказательство реализации

### Конструктивное

Реализовано в шаблонах Squid и задачах Ansible:
- `workers` по числу виртуальных процессоров (директива выпускается при более чем одном), одинаково на обоих уровнях.
- `cache_mem` — 25% предела памяти службы в бюджете узла.
- Sysctl: задача `ansible.posix.sysctl` с `reload: true`.
- Systemd override: `LimitNOFILE={{ fd_limit }}` и два порога памяти.

### Аналитическое

**Единое правило для обоих уровней:** число рабочих процессов задаётся числом виртуальных процессоров узла. Отдельная настройка для access не понадобилась: узлы обоих уровней разворачиваются из одного инвентори и имеют сопоставимые ресурсы, а при единственном процессоре директива не выпускается сама собой.

**Увеличенное ожидание ответа:** AI API с длинными запросами обдумывают ответ десятки минут, поэтому умолчание шаблона (15 минут) поднято инвентори до 30. Прочие таймауты оставлены короткими намеренно: они относятся к установлению соединения и к паузам между запросами, где длинное ожидание удерживает дескрипторы без пользы.

**Динамические формулы:** серверы могут иметь разные конфигурации; формулы автоматически адаптируют параметры.

### Негативное

| Риск | Митигация |
|---|---|
| OOM при большом количестве соединений | Два порога cgroup: на мягком — вытеснение, жёсткий гасит одну службу, а не узел |
| Исчерпание fd | `fd_limit` ≥ 65535 на уровне systemd и limits.d; мониторинг через squidclient |
| Conntrack table overflow | nf_conntrack_max = 262144; мониторинг |
