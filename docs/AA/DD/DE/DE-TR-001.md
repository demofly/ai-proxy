# DE-TR-001 — Транзитный поток запросов

**Последняя правка AI:** 2026-08-29T07:40:00Z

## Описание

Транзитный поток — данные пользовательских обращений к AI API, проходящие через оба уровня проксирования. Отличается от прочих сущностей корпуса тем, что **нигде не хранится**: существует только в памяти рабочих процессов Squid и на сетевых соединениях, а после закрытия соединения не остаётся ни в каком виде.

Сущность заведена именно поэтому: не описав её, легко счесть, что содержимое обращений где-то оседает. Это данные объекта защиты (обращения пользователей), а не данные самого прокси.

## Атрибуты

| Атрибут | Тип | Описание | Обязательность |
|---|---|---|---|
| method | string | Метод HTTP; для трафика к AI API — всегда `CONNECT` | Обязательный |
| target | string | Имя узла и порт назначения (`api.anthropic.com:443`) | Обязательный |
| username | string | Имя пользователя из заголовка `Proxy-Authorization` | Обязательный на access-уровне |
| payload | двоичный поток | Содержимое туннеля: TLS-записи между клиентом и AI API | Обязательный |

## Хранилище

| Параметр | Значение |
|---|---|
| **Путь** | Отсутствует: данные не записываются на диск ни на одном узле |
| **Формат** | Поток TCP; после установления туннеля — шифрованные записи TLS |
| **Место существования** | Память рабочего процесса Squid и буферы ядра |
| **Время жизни** | Длительность соединения |
| **Компоненты** | [C3-SA-001](../../C3/C3-SA-001.md), [C3-SU-001](../../C3/C3-SU-001.md) |

## Границы наблюдаемости

| Что видит система | Что не видит |
|---|---|
| Имя узла назначения и порт (из строки `CONNECT`) | Содержимое запросов и ответов: туннель зашифрован сквозным TLS между клиентом и AI API |
| Имя пользователя, объём переданных байтов, длительность | Заголовки и тело обращений к AI API |
| Адрес клиента на access-уровне | Адрес клиента на upstream-уровне: заголовки идентификации удалены |

Из этого следует, что **пережатие, фильтрация по содержимому и разбор обращений на прокси невозможны** — не по недоработке, а по устройству сквозного шифрования. Прокси распоряжается только метаданными соединения.

## Жизненный цикл

| Стадия | Действие | Актор | Инструмент |
|---|---|---|---|
| **Create** | Клиент открывает соединение и посылает `CONNECT` | Клиент | IDE, браузер, оболочка |
| **Use** | Проверка подлинности и домена, выбор пира, установление туннеля | Squid access | ACL, `cache_peer` |
| **Transfer** | Пересылка потока на upstream, оттуда — к AI API | Squid upstream | Туннель TCP |
| **Dispose** | Закрытие соединения; данные исчезают вместе с буферами | Ядро | — |

Записи о факте обращения остаются только в журнале ([DE-LG-001](DE-LG-001.md)) и только на access-уровне.

## Безопасность

| Параметр | Значение |
|---|---|
| **Уровень конфиденциальности** | Высокий: содержимое обращений к AI API — рабочие данные инженеров |
| **Защита при передаче** | Сквозной TLS между клиентом и AI API; прокси его не расшифровывает |
| **Защита на участке клиент → access** | Заголовок `Proxy-Authorization` передаётся открытым текстом при обычном HTTP-подключении к прокси — открытый разрыв GAP-005 |
| **Анонимизация к моменту выхода** | На upstream удалены `X-Forwarded-For`, `Via`, `X-Real-IP`; имя прокси скрыто |
