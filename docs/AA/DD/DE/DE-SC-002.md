# DE-SC-002 — Ключ и сертификат терминации MTProxy

**Последняя правка AI:** 2026-08-29T07:43:02Z

## Описание

Пара «закрытый ключ и самоподписанный сертификат», которой маршрутизатор потоков
на upstream-узле терминирует TLS для MTProxy. Порождается при развёртывании командой
создания самоподписанного сертификата и на узле остаётся до его пересоздания.

Существенное отличие от прочих секретов проекта: этот **порождается на самом узле**,
а не приходит из инвентори. Его нет ни в репозитории, ни в файле переменных, и при
переустановке узла он будет иным.

## Атрибуты

| Атрибут | Тип | Описание | Обязательность |
|---|---|---|---|
| Закрытый ключ | Файл PEM | Ключ терминации, `/etc/nginx/ssl/mtproxy.key` | Обязательный при `mtproxy_enabled` |
| Сертификат | Файл PEM | Самоподписанный, `/etc/nginx/ssl/mtproxy.crt` | Обязательный при `mtproxy_enabled` |

## Хранилище

| Параметр | Значение |
|---|---|
| **Путь** | `/etc/nginx/ssl/` на upstream-узле |
| **Права каталога** | `0700`, владелец — суперпользователь |
| **Права ключа** | `0600`, владелец — суперпользователь |
| **Порождение** | Команда создания самоподписанного сертификата при развёртывании; повторно не выполняется, если файл уже есть |
| **Компонент** | [C3-NX-001](../../C3/C3-NX-001.md) — маршрутизатор потоков |

## Жизненный цикл

| Стадия | Действие | Актор |
|---|---|---|
| Создание | Порождается при первом развёртывании роли MTProxy | Ansible |
| Использование | Терминация TLS между узлами на промежуточном участке передачи | nginx |
| Обновление | Не выполняется: срок действия не отслеживается, обновления по расписанию нет |  — |
| Уничтожение | Вместе с узлом либо удалением каталога вручную | Оператор |

## Безопасность

| Параметр | Значение |
|---|---|
| **Уровень конфиденциальности** | Высокий: закрытый ключ |
| **Подлинность не проверяется** | Принимающая сторона проверку сертификата не выполняет — он самоподписанный, и обмен между узлами защищён только шифрованием |
| **Область ущерба при утрате** | Ограничена участком между access- и upstream-узлами: сквозной обмен клиента с Telegram защищён собственным протоколом MTProxy |

Отсутствие проверки подлинности означает, что шифрование на этом участке защищает
от чтения, но не от подмены стороны. Ущерб от этого ограничен: обмен внутри уже защищён
протоколом MTProxy с общим секретом.
