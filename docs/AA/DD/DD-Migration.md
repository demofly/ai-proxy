# DD-Migration — Миграция данных

**Последняя правка AI:** 2026-08-29T03:50:00Z

## Описание

Документ описывает стратегию и историю миграций данных проекта AI Assistants Proxy. Проект не использует традиционные СУБД, поэтому миграции данных относятся к изменениям форматов конфигурационных файлов и архитектурным переходам.

## Общая стратегия

- **Нет миграций БД** — проект не использует базы данных
- **Миграции конфигураций** — изменения форматов выполняются через Ansible roles с поддержкой обратной совместимости
- **Паттерн:** Expand-Contract — сначала поддержка обоих форматов, затем удаление устаревшего
- **Откат:** каждая миграция поддерживает rollback через Ansible handlers или отдельные tasks

## Реестр миграций

Миграции реализованы задачами Ansible, снимающими артефакты прежних топологий при очередном развёртывании. Задачи идемпотентны: на узле, где прежней конфигурации нет, они ничего не делают. Полный перечень — в ролях `mtproxy`, `nginx` и в плейбуке (задачи с именами, начинающимися на `Migration:`).

### MIG-001: mtg.env → mtg.toml (MTProxy v2)

| Параметр | Значение |
|---|---|
| **ID** | MIG-001 |
| **Дата** | Реализовано в текущей версии |
| **Сущность** | [DE-SC-001](DE/DE-SC-001.md), [DE-CF-001](DE/DE-CF-001.md) |
| **Компонент** | [C3-MT-001](../C3/C3-MT-001.md) — MTProxy (mtg) |
| **Причина** | Переход mtg v1 (env-файл) → mtg v2 (TOML-конфигурация) |
| **Обратимость** | Нет (mtg v2 не поддерживает env-формат) |
| **Статус** | Завершена |

**Детали миграции:**

| Параметр | Старый формат (mtg.env) | Новый формат (mtg.toml) |
|---|---|---|
| Секрет | `MTPROTO_SECRET=<hex>` | `secret = "<hex>"` |
| Привязка | `MTPROTO_BIND=:443` | `bind-to = "127.0.0.1:2083"` |
| Формат файла | Environment variables (.env) | TOML key-value pairs |
| Путь | `/etc/mtproxy/mtg.env` | `/etc/mtproxy/mtg.toml` |

**Процедура:** Ansible role `mtproxy` автоматически:
1. Останавливает старый сервис mtg (если запущен)
2. Удаляет старый конфигурационный файл mtg.env
3. Генерирует новый mtg.toml из Jinja2-шаблона
4. Перезапускает сервис

### MIG-002: Squid direct :443 → nginx:443 + Squid:3128

| Параметр | Значение |
|---|---|
| **ID** | MIG-002 |
| **Дата** | Реализовано в текущей версии |
| **Сущность** | [DE-CF-001](DE/DE-CF-001.md) |
| **Компонент** | [C3-NX-001](../C3/C3-NX-001.md) — nginx SNI Router, [C3-SA-001](../C3/C3-SA-001.md) — Squid Access Proxy |
| **Причина** | Совместное использование порта 443 с MTProxy (SNI routing) |
| **Обратимость** | Да (установить `behind_nginx: false` в inventory) |
| **Статус** | Завершена |

**Детали миграции:**

| Параметр | До миграции | После миграции |
|---|---|---|
| Squid listen | `0.0.0.0:443` | `127.0.0.1:3128` |
| nginx | Не установлен | stream SNI router на `0.0.0.0:443` |
| MTProxy доступ | Недоступен на access tier | Через nginx SNI routing |
| Переключатель | — | `behind_nginx: true/false` в inventory |

**Процедура отката:** установить `behind_nginx: false` в inventory.yml → запустить playbook → Squid вернётся на прямое прослушивание :443, nginx будет удалён/остановлен.

### MIG-004: маршрутизатор SNI переведён на передачу адреса источника

| Параметр | Значение |
|---|---|
| **ID** | MIG-004 |
| **Дата** | 2026-04-16 |
| **Сущность** | [DE-CF-001](DE/DE-CF-001.md), [DE-LG-001](DE/DE-LG-001.md) |
| **Компонент** | [C3-NX-001](../C3/C3-NX-001.md), [C3-SA-001](../C3/C3-SA-001.md) |
| **Причина** | Без передачи адреса источника журнал Squid фиксировал бы `127.0.0.1` вместо адреса клиента, а обнаружение вторжений теряло бы смысл |
| **Обратимость** | Да: снять `proxy_protocol on` в маршрутизаторе и `require-proxy-header` в Squid — обе стороны меняются одновременно |
| **Статус** | Завершена |

**Детали:** общий файл маршрутизатора принудительно обновляется даже там, где он уже существовал (обычное правило «первый развернувший побеждает» здесь отменяется), поскольку иначе узлы с прежней конфигурацией остались бы без передачи адреса.

## Действующие миграционные задачи и срок их жизни

Задачи, снимающие артефакты прежних конфигураций, накапливаются в ролях бессрочно. Каждая
идемпотентна: на узле, где прежней конфигурации нет, она ничего не делает. Плата за это —
рост плейбука и время прогона; кроме того, задача, чьё назначение забыто, мешает читать код.

**Критерий снятия:** задачу можно убрать, когда все узлы, на которые проект когда-либо
разворачивался, прошли её хотя бы раз. Проверяется отсутствием снимаемого артефакта на всех
узлах инвентори — не рассуждением, а осмотром. До такой проверки задача остаётся: её
удаление ценой ошибки оставит на узле конфигурацию, конфликтующую с текущей.

| Задача | Роль | Что снимает | Введена |
|---|---|---|---|
| Обезвреживание прежнего файла источников | `crowdsec` | Общий `acquis.yaml`, порождённый этой ролью | 2026-08-29 |
| Обновление маршрутизатора SNI до передачи адреса источника | `nginx`, `mtproxy` | Прежний файл маршрутизатора без `proxy_protocol` | 2026-04-16 |
| Удаление монолитной конфигурации потока | `nginx`, `mtproxy` | `mtproxy-tls.conf`, прежний блок с меткой в `nginx.conf` | 2026-04-16 |
| Удаление конфигурации access-стороны с upstream | `mtproxy` | `10-aiproxy-upstreams.conf` и запись карты имён, ошибочно развёрнутые на upstream | 2026-04-16 |
| Удаление терминатора TLS для Squid | `mtproxy` | `10-squid-tls-term.conf` и запись Squid в карте имён | 2026-04-16 |
| Отключение включённого по умолчанию сайта nginx | `mtproxy` | `sites-enabled/default` | 2026-04-16 |
| Удаление правила UFW для Squid на 443 | плейбук | Правило, открывавшее Squid вне списка адресов | 2026-08-28 |

Столбец «Введена» позволяет судить о сроке: задача, введённая при переходе, которому больше
года, с высокой вероятностью уже отработала везде — но подтверждается это осмотром узлов,
а не давностью.
