## Действующие механизмы проверки

Перечень того, что проверяется при развёртывании на самом деле; прочие правила выше
опираются на порождение конфигураций из единого источника либо на ручную сверку.

| Механизм | Что проверяет | Где |
|---|---|---|
| `squid -k parse` | Синтаксис конфигурации Squid до её применения | Задачи развёртывания обоих уровней и роль nginx |
| `unbound-checkconf` | Синтаксис конфигурации резолвера | Роль `dns_resolver` |
| `nft -c -f` | Синтаксис правил nftables | Ветка nftables в плейбуке |
| `iptables-restore --test` | Синтаксис правил iptables | Ветка iptables в плейбуке |
| `sshd -t -f` | Синтаксис конфигурации SSH | Задача усиления доступа |
| `assert` бюджета памяти | Сумма пределов служб не превышает доступного объёма узла | Плейбук, фаза расчёта памяти |
| `assert` наполненности файла паролей | В файле есть хотя бы одна учётная запись, если проверка подлинности включена | Плейбук, до развёртывания |
| `assert` резерва под соседей | При совместном размещении резерв памяти под соседние проекты не равен нулю: иначе обе проверки бюджета проходят независимо | Плейбук, фаза расчёта памяти |
| `assert` ограничения резолвера | Порт 53 закрыт для всех, кроме access-узлов, по действующим правилам ядра | Плейбук, фаза проверки экрана |

Проверка синтаксиса выполняется до записи файла: непрошедшая конфигурация не заменяет
действующую, поэтому ошибка шаблона не выводит службу из строя.
