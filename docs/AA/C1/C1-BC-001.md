## Описание

**AI Assistants Proxy** — корпоративный сервис проксирования доступа к западным AI API для инженерной команды Организации. Система обеспечивает безопасный, анонимный и отказоустойчивый доступ к AI-сервисам (Claude, ChatGPT, Gemini, GitHub Copilot, Cursor и др.) через единый статичный эндпоинт на территории Российской Федерации.

### Архитектурная концепция

Система реализует **двухуровневую архитектуру проксирования**:

1. **Access tier (РФ)** — точка входа для пользователей. Обеспечивает аутентификацию, авторизацию, журналирование обращений и кеширование ответов. Отказоустойчивость по виртуальному IP (VRRP) — опциональная возможность уровня: она включается на площадке, где access-узлы делят общую подсеть, и по умолчанию выключена ([C2-NF-001](../C2/C2-NF-001.md)).

2. **Upstream tier (вне РФ)** — анонимный транспортный уровень. Минимальная конфигурация, отсутствие журналирования и аутентификации. Управление доступом по IP-адресам access-прокси.

Оба уровня построены на базе прокси-сервера **Squid**. Инфраструктура управляется через **Ansible** (IaC — Infrastructure as Code).

Разрешение доменных имён вынесено в собственный кеширующий резолвер на каждом узле: access-узлы пересылают запросы на резолверы upstream-узлов, те обращаются к публичным DNS. Наружу порт резолвера открыт только адресам access-прокси. Запрашиваемые имена перестают быть видны провайдеру РФ и публичным резолверам, однако пересылка между уровнями идёт обычным DNS: на транзитном участке между площадками имена по-прежнему наблюдаемы. Полный перечень того, что мера даёт и чего не даёт, — в [ADR-000009](../ADR/ADR-000009.md) ([C2-NF-002](../C2/C2-NF-002.md), [C2-NF-003](../C2/C2-NF-003.md)).

### Дополнительные возможности

Система поддерживает **co-deployment** — совместное размещение на одних серверах с другими проектами. Маршрутизация трафика на порту 443 реализована через **nginx SNI Router**, обеспечивающий бесконфликтное разделение TLS-потоков по SNI (Server Name Indication).

На upstream-нодах дополнительно развёрнут **MTProxy (mtg)** — прокси для Telegram с обходом DPI через fake-TLS маскировку.

**Компоненты контекстной диаграммы:**

| Элемент | Тип | Описание |
|---|---|---|

| Upstream Proxy (вне РФ) | Часть целевой системы | Анонимный транспортный уровень |
| MTProxy (mtg, upstream) | Часть целевой системы | Прокси Telegram за маршрутизатором SNI |
| Ansible Deployment | Часть целевой системы | Развёртывание и конфигурирование обоих уровней |
| Инженер-разработчик | Актор | Пользователь AI-инструментов через IDE или браузер |
| DevOps-инженер | Актор | Оператор инфраструктуры, развёртывание и обслуживание |
| Telegram-пользователь | Актор | Клиент Telegram, подключающийся через MTProxy |
| AI API (Claude, ChatGPT, Gemini, Copilot, …) | Внешняя система | Целевые AI-сервисы |
| DNS (Quad9, Google, Cloudflare) | Внешняя система | Разрешение доменных имён; обращается резолвер upstream-узла |
| CrowdSec Central API | Внешняя система | Репутационные данные и сценарии обнаружения для IPS |
| Telegram DC | Внешняя система | Центры обработки данных Telegram |

### Границы системы

**Входит в scope:**
- Серверная прокси-инфраструктура (Ansible roles, playbooks, templates)
- Конфигурации клиентов (IDE, браузер, PowerShell)
- Документация развёртывания и эксплуатации

**Не входит в scope:**
- Сами AI-сервисы (Claude API, OpenAI API и др.)
- Серверы, на которых развёрнута инфраструктура (предоставляются Организацией)
- Сетевая связность между РФ и зарубежными площадками
- Биллинг и подписки на AI-сервисы
