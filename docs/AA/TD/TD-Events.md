# TD-Events — Каталог событий

**Последняя правка AI:** 2026-08-29T07:37:34Z

## Описание

Перечень событий, наблюдаемых на узлах инфраструктуры: что происходит, кто это фиксирует
и в каком виде. Каталог служит отправной точкой при разборе происшествия — по нему видно,
в каком журнале искать след конкретного события.

Где именно лежат журналы — [TD-Logs.md](TD-Logs.md); числовые показатели —
[TD-Metrics.md](TD-Metrics.md); функциональные области, к которым события отнесены, —
[TD-FA.md](TD-FA.md).

## События

| ID | Событие | Источник | Формат | ФО | Описание |
|---|---|---|---|---|---|
| EV-01 | Запись об обращении | Squid на access-узле, при включённом журналировании | Текстовая запись **встроенного формата** Squid: собственный формат проектом не задаётся | ФО-01, ФО-02 | Каждый HTTP/HTTPS-запрос через access-прокси: timestamp, client IP, метод, URL, статус, размер, пользователь |
| EV-02 | CrowdSec alert | CrowdSec Agent | JSON (CrowdSec API) | ФО-02 | Обнаружение аномального поведения: bruteforce, сканирование, нарушение ACL |
| EV-03 | Смена владельца виртуального адреса | Keepalived — **только при включённом `enable_keepalived`**, в образце инвентори он выключен | Системный журнал | ФО-03 | Переход VRRP-состояния: MASTER → BACKUP, BACKUP → MASTER, FAULT |
| EV-04 | Блокировка и её снятие | Решение принимает агент, применитель переносит его в правила экрана — это разные службы | Правила экрана и перечень решений агента | ФО-02 | Блокировка/разблокировка IP-адреса по решению CrowdSec |
| EV-05 | Systemd unit state | systemd | journald | ФО-06 | Изменение состояния сервисов: start, stop, fail, restart |
| EV-06 | Маршрутизация потока: и успешная, и отказавшая | nginx | Журнал обращений потокового режима (`/var/log/nginx/sni-router.log`) и `error.log` | ФО-04 | Запись несёт адрес клиента, запрошенное имя SNI, адрес назначения, код завершения сессии и объём. Вид записи подогнан под парсер `crowdsecurity/nginx-logs` действующей коллекции: собственного парсера для потокового режима не существует. ЦЕНА: узел хранит след того, к каким сервисам обращались, что ослабляет неразличимость обращений — включено решением владельца ради разбора происшествий |
| EV-07 | Подключение к MTProxy | mtg | Журнал systemd. Уровень журналирования службы проектом не задаётся, и пишет ли она о каждом подключении при умолчании — из конфигурации не следует; проверяется на узле | ФО-05 | Подключение/отключение Telegram-клиента |
| EV-08 | Отказ либо перезапуск резолвера | unbound | journald | ФО-07 | Служба не отвечает на настроенных адресах; проверка после развёртывания перезапускает её при расхождении |
| EV-09 | ~~Отброшенный запрос к резолверу~~ **событием не является** | межсетевой экран узла | Запись об отбрасывании в правилах закомментирована: остаётся счётчик, то есть величина, а не событие. Учтена в каталоге метрик ([TD-Metrics.md](TD-Metrics.md), MET-10). Чтобы событие появилось, нужно раскомментировать запись в шаблоне правил (`nft list`, `iptables -L -v`, `ufw status verbose`) | ФО-07 | Обращение к порту 53 с адреса вне списка разрешённых |
| EV-10 | Остановка развёртывания по бюджету памяти | Ansible (`assert`) | вывод выполнения плейбука | ФО-06 | Сумма пределов служб превысила доступный объём узла |
| EV-11 | Попытка входа по SSH, успешная либо нет | sshd | Системный журнал аутентификации и журнал юнита | ФО-02 | Основа обнаружения на upstream-узлах: журнал обращений там выключен, и это единственный источник, по которому обнаружение работает |
| EV-12 | Результат проверки службы Squid | Сценарий проверки, вызываемый Keepalived | Системный журнал, метка `keepalived-chk` | ФО-03 | Неудача трижды подряд приводит к смене владельца виртуального адреса; при выключенном `enable_keepalived` события нет |
