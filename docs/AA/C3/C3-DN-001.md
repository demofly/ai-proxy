# C3-DN-001 — DNS Resolver (Unbound)

**Последняя правка AI:** 2026-10-19T14:19:57Z

## Описание

Unbound на каждом узле обслуживает Squid и ОС на `127.0.0.1:53`.
На access запросы идут в локальный dnsproxy (`127.0.0.1:5353`), который обращается
к upstream только по DoH на общем `proxy_port` (443), SNI `dns.transit.internal`. TLS-проверка upstream намеренно
отключена; буквальные IP устраняют bootstrap DNS, fallback отсутствует.
Upstream Unbound обращается к `dns_servers` по обычному DNS.

Публичный DoH access `https://<dns_doh_hostname>/q` доступен всем. Общий SNI router
на 443 направляет соединение в TLS-терминатор nginx на 4446; тот снимает PROXY
заголовок и передаёт HTTP/2 на Unbound `127.0.0.1:5443`. Поддерживаются GET/POST
RFC 8484, TLS 1.2/1.3. Отдельная публичная UDP-служба не создаётся.

### Интерфейсы и доступ

**Спецификации контрактов:** [C3-DN-001-Config](../Interfaces/User/C3-DN-001-Config.md).

| Интерфейс | Потребители | Ограничения |
|---|---|---|
| `127.0.0.1:53` UDP/TCP | Squid и ОС | Только loopback |
| `upstream:443`, SNI `dns.transit.internal`, `/q` HTTPS HTTP/2 | dnsproxy access | Firewall и ACL по `dns_allowed_clients` |
| `https://<dns_doh_hostname>/q` на access:443 | Любые DoH-клиенты | Без авторизации и allowlist |
| `127.0.0.1:5353` / `5443` | Внутренний транспорт / nginx | Только loopback |

Обычный внешний DNS 53 закрыт. На upstream список `dns_allowed_clients` общий
для firewall и Unbound: IP `access_proxies` плюс `dns_extra_clients`.
Публичный сертификат выдаётся и продлевается Certbot отдельно на каждом access;
HTTP-01 работает через любой IP и оба HTTPS-имени, без копирования ключей.

### Ресурсы и кеширование

Unbound: минимум 24 МиБ; `threads=min(CPU,max(MemoryMax/64,1))`, базовый кеш
`max(MemoryMax/24,1)` МиБ. Проверяется `10*cache+4*threads+8 <= MemoryMax`.
HTTP/2 query/response buffers по 256 КиБ, не более 16 streams на соединение.
Dnsproxy: минимум 32 МиБ, `GOMEMLIMIT=16MiB`, до 64 обработчиков, таймаут 4 с;
параллельные upstream, первый успешный ответ. Оба процесса учтены общим бюджетом.

TTL Unbound следует зоне; переменные min/max/negative TTL удалены ранее и не
поддерживаются. `serve-expired` выключен. Dnsproxy не кеширует. Собственный кеш
Squid остаётся отдельным: положительный предел 6 часов, отрицательный 30 секунд.
DNSSEC проверяется Unbound; TLS без проверки сертификата не удостоверяет upstream
и не защищает неподписанные зоны от активной подмены на пути.

### Порядок применения

Сначала готовятся бинарники и staged конфиги, SNI router upstream, затем firewall.
Активируется upstream, проверяется DoH с access, затем переключается access.
Выпуск публичных сертификатов выполняется после готовности DNS. Системный resolv.conf переключается
только после корректного ответа. Digest применяется с подтверждением после
проверки; прерванное применение восстанавливается повторным прогоном.
Первый переход выполняется полным плейбуком на всех узлах, без `-t dns` и без
отдельного upstream-only прогона.

Между access и upstream используются постоянные HTTP/2-соединения поверх
**TLS 1.3**. Пул транспорта dnsproxy v0.86.0 повторно использует соединения и
закрывает их через 300 секунд без DNS-запросов; это отличается от таймаута
отдельного запроса (4 с). `tcp-idle-timeout` upstream Unbound также равен
300000 мс. После простоя следующий запрос создаёт новое TLS-соединение;
активный поток запросов не обрывается по возрасту соединения.

В Unbound 1.19 нет директивы `tls-protocols`: TLS 1.3 задаётся через отдельный
`/etc/unbound/openssl-doh.cnf` и переменную `OPENSSL_CONF` только для upstream
unbound.service. Общая политика OpenSSL узла и клиентский TLS публичного DoH
не меняются. Нативная проверка отклоняет TLS 1.2 и принимает TLS 1.3.
`tests/check_doh_idle.py` наблюдает реальное соединение более пяти минут,
проверяет сохранение до таймаута и новое соединение после него.

## Критерии приёмки

| Критерий | Проверка | Результат |
|---|---|---|
| Локальный DNS | `dig @127.0.0.1 example.com` | NOERROR |
| DNSSEC | `dig @127.0.0.1 dnssec-failed.org` | SERVFAIL |
| Каждый upstream | DoH POST с каждого access | HTTP/2, DNS NOERROR |
| Публичный DoH | GET/POST `/q` через каждый access | HTTP/2, доверенный сертификат |
| Автопродление | HTTP-01 обоих имён через оба IP | Локальные/соседние токены 200, отсутствие 404 |
| Ограничение upstream | Действующие firewall и ACL | DoH только access, внешний 53 закрыт |
| NAT | Проверка локального слушателя и с access | Нет проверки собственного внешнего IP |
| Память транспорта | 2000 запросов, 32 одновременно, отдельный cgroup 32M | Без OOM/рестартов |

## Доказательство реализации

Роль `Servers/deploy/roles/dns_resolver/`: `main.yml` готовит отдельный staged config, `doh-router.yml` — SNI relay,
`doh-bridge.yml` устанавливает pinned dnsproxy с SHA256, `doh-upstream.yml`
готовит самоподписанный сертификат, `activate.yml` применяет и проверяет DNS.
Публичный TLS/SNI/ACME — `roles/nginx/tasks/doh.yml`; адреса без bootstrap —
`filter_plugins/dns.py`; общая координация ACME — `filter_plugins/acme.py`.
Нативные проверки: `tests/test_dns_doh.py`, `tests/test_acme_cluster.py`,
`tests/check_doh_budget.py`. Операционные команды и все параметры:
[руководство деплоймента](../../../Servers/deploy/README.md).
