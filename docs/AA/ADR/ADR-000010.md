# ADR-000010 — Пулы пользователей: объединение наборов upstream, общие access

## Контекст

До решения все аутентифицированные пользователи распределялись `userhash` по одному набору upstream. Набор задавался на каждый access-узел переменной `squid_upstream_hosts`, по умолчанию — вся группа `upstreams`. Владелец поставил задачу: группа пользователей ассоциируется с пулом, пул — с набором upstream, access общие. По умолчанию нужны два пула: один со всеми пользователями, второй пустой и по пользователям, и по upstream.

## Решение

Решения приняты владельцем 2026-11-06 выбором из перечисленных вариантов:

1. **Членство — объединение.** Пользователь получает объединение upstream всех пулов своих групп. Особая группа `all` означает буквально всех пользователей `passwd`.
2. **Описание — в inventory.** Переменные `proxy_user_groups` и `proxy_pools` лежат в частном `inventory.yml`, образец — в `inventory.yml.sample`. Имена пользователей сверяются с `passwd` при развёртывании.
3. **Пул заменяет перечень узла.** `squid_upstream_hosts` упраздняется. Заданная переменная останавливает развёртывание с указанием перенести перечень в пул. Пул по умолчанию включает все upstream.
4. **Пустой набор — явный отказ.** Пользователь с пустым объединением получает HTTP 403 правилом `http_access` до разрешающих правил, независимо от `allow_direct_fallback`.

Реализация: ACL `proxy_auth` на пул, `cache_peer_access` на пира, правило отказа с завершающим `all` (без него последний `proxy_auth` в строке `deny` вызвал бы повторный запрос 407).

## Отклонённые альтернативы

| Развилка | Альтернатива | Причина отклонения |
|---|---|---|
| Членство | ровно один пул на пользователя, `all` = «все, кто не назначен в другой пул» | выбор владельца — объединение |
| Членство | первый подходящий пул по порядку | выбор владельца — объединение |
| Хранение | отдельный частный файл `groups` в формате Apache AuthGroupFile | выбор владельца — inventory |
| Сочетание с узлом | пересечение пула с перечнем узла, пустое — ошибка либо отказ | выбор владельца — пул заменяет перечень |
| Сочетание с узлом | узкий перечень исключённых линий на access | выбор владельца — пул по умолчанию включает все upstream, риск линии одного из access к одному из upstream, обрывавшей ответы, принят |
| Пустой набор | ошибка развёртывания | отказ 403 оставляет развёртывание возможным при пустом втором пуле по умолчанию |
| Пустой набор | прямой выход с access | раскрывает адрес access целевому сервису — то, ради сокрытия чего построен второй уровень |

## Последствия

- Изоляция пользователей между пулами не гарантируется: членство в пуле с `all` даёт пользователю все upstream этого пула. Для изоляции upstream, отведённые группе, не должны входить ни в один пул с группой `all`.
- Обход неисправной линии одного access к одному upstream больше не задаётся на узле. Он доступен только исключением upstream из пула для всех access.
- Смена состава группы требует развёртывания конфигурации Squid, а не только тега `passwd`.
