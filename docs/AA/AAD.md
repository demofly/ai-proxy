# AAD — Консолидированное описание архитектуры

**Последняя правка AI:** 2026-10-19T15:17:22Z

## Описание

Документ объединяет все архитектурные решения ([ADL.md](ADL.md)) в связное описание архитектуры системы AI Assistants Proxy. Каждое решение вносит вклад в определённый аспект архитектуры; вместе они формируют целостный архитектурный образ системы.

## Архитектурная концепция

AI Assistants Proxy — корпоративный сервис проксирования доступа к западным AI API ([C1-BC-001](C1/C1-BC-001.md)). Архитектура системы строится на следующих ключевых решениях:

### 1. Двухуровневая архитектура ([ADR-000001](ADR/ADR-000001.md))

Фундаментальное архитектурное решение — разделение на два физически разнесённых уровня:

- **Access tier (РФ):** точка входа для пользователей. Аутентификация, авторизация, журналирование, кеширование; переключение по виртуальному адресу — опция, по умолчанию выключенная. В образце инвентори два узла. Squid за маршрутизатором SNI (:443 → `127.0.0.1:3128`).
- **Upstream tier (вне РФ):** анонимный транспорт. Минимальная конфигурация, без журналирования, без проверки подлинности. В образце инвентори два узла. Squid также за маршрутизатором SNI: внешний порт 443, локально `127.0.0.1:3128` с `require-proxy-header`.

Разделение обусловлено необходимостью обхода гео-ограничений AI-сервисов при сохранении контроля доступа и анонимности на территории РФ.

### 2. Squid как прокси-движок ([ADR-000002](ADR/ADR-000002.md))

Оба уровня построены на базе **Squid** — зрелого HTTP/HTTPS прокси-сервера с поддержкой:
- CONNECT-туннелирования (TLS passthrough без расшифровки)
- Basic Auth через ncsa_auth
- ACL-фильтрации доменов (dstdomain, dstdom_regex)
- Кеширования (ufs)
- SMP-параллелизма (workers)
- Каскадирования (cache_peer)

Access-прокси каскадирует запросы на upstream через `cache_peer` с балансировкой `userhash`.

### 3. Отказоустойчивость ([ADR-000006](ADR/ADR-000006.md))

На access-уровне реализован VRRP failover через **Keepalived**:
- Виртуальный IP (VIP) — единая точка входа
- Автоматическое переключение MASTER → BACKUP при отказе
- Health-check: мониторинг процесса Squid (vrrp_script)

На upstream-уровне балансировка реализована через Squid `userhash`:
- Распределение запросов между upstream-нодами
- Автоматический failover при недоступности peer

### 4. Безопасность ([ADR-000004](ADR/ADR-000004.md))

Многослойная защита:
- **CrowdSec** — IPS с коллаборативной репутационной базой (все ноды, whitelist инфраструктуры)
- **Межсетевой экран** — на upstream-узле входящие разрешены только адресам access-прокси; бэкенд выбирается по состоянию ufw и дистрибутиву (UFW, nftables либо собственная цепочка iptables), набор закрываемых портов одинаков во всех трёх ветках. Блокировки CrowdSec применяются параллельно через собственную таблицу
- **Squid ACL** — фильтрация по белому списку доменов
- **Анонимизация** — удаление заголовков X-Forwarded-For, Via на upstream
- **Разрешение имён** — собственный резолвер на каждом узле, порт 53 upstream-узла открыт только access-адресам ([ADR-000009](ADR/ADR-000009.md))

### 5. Co-deployment ([ADR-000003](ADR/ADR-000003.md), [ADR-000005](ADR/ADR-000005.md))

Upstream-ноды используются совместно с другими проектами:
- **nginx SNI Router** — L4-маршрутизация TLS-потоков по SNI на порту 443
- **MTProxy (mtg)** — прокси для Telegram с fake-TLS маскировкой

На обоих уровнях nginx:443 разводит потоки одинаково: обращение с именем SNI, равным `mtproxy_fake_tls_domain`, уходит в MTProxy, всё прочее — в Squid как бэкенд по умолчанию. Соединение без TLS ClientHello (CONNECT от access-узла) имени SNI не несёт и потому попадает в тот же бэкенд по умолчанию.

### 6. Разрешение имён каскадом ([ADR-000009](ADR/ADR-000009.md))

На каждом узле работает кеширующий резолвер Unbound. Access-узлы пересылают запросы через локальный dnsproxy только по DoH (без проверки сертификата) на резолверы upstream-узлов, те обращаются к публичным резолверам из `dns_servers`. Squid и системные утилиты спрашивают `127.0.0.1`. Перечень имён, запрашиваемых с территории РФ, наружу не уходит, а внешний порт 53 закрыт; публичный DoH access доступен всем и имеет автоматически продляемый сертификат на каждом IP. URI-путь задаётся `dns_doh_path` в inventory (по умолчанию `/q`); клиенты access используют настройку каждого upstream.

### 7. Бюджет памяти узла ([ADR-000008](ADR/ADR-000008.md))

Каждой службе назначается предел памяти средствами systemd: мягкий на уровне 80 % и жёсткий, вдвое превышающий ожидаемое потребление. Сумма пределов сверяется с объёмом, доступным на узле после вычета резерва ядра и памяти соседних проектов; нехватка останавливает развёртывание, а не обнаруживается под нагрузкой.

### 8. Infrastructure as Code ([ADR-000007](ADR/ADR-000007.md))

Вся инфраструктура управляется через **Ansible**:
- Единый `playbook.yml` — точка входа
- Роли: `dns_resolver`, `crowdsec`, `nginx`, `mtproxy`; inline-задачи для Squid, Keepalived, клиентских конфигураций
- Идемпотентное выполнение
- Inventory-driven конфигурация
