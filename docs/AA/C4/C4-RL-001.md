## Описание

Директория `Servers/deploy/roles/crowdsec/` -- Ansible-роль для установки и настройки CrowdSec IPS (Intrusion Prevention System) с firewall bouncer на nftables. CrowdSec обеспечивает коллективную защиту от атак: локальные детекции + TI-фиды от сообщества (70k+ серверов) через CAPI.

### Состав роли

| Файл | Описание |
|---|---|
| `tasks/main.yml` | Одна пакетная транзакция, конфиги, управляемая синхронизация Hub и условный reload systemd |
| `handlers/main.yml` | Применение движка через tasks/apply.yml и отдельный restart bouncer |
| `tasks/apply.yml` | Проверка crowdsec -t, применение и подтверждение снимка Hub |
| `scripts/sync-crowdsec-hub.py` (deploy/scripts) | TTL, проверка содержимого, пакетная установка недостающих коллекций, восстановление после прерывания |
| `templates/acquis.yaml.j2` | Источники записей для обнаружения: журнал Squid (метка `squid`, разбора для неё не существует) и журнал маршрутизации по имени SNI (метка `nginx`, разбирается парсером коллекции). Кладётся в `acquis.d/` отдельным файлом проекта, общий `acquis.yaml` не перезаписывается |
| `templates/whitelist-infrastructure.yaml.j2` | Список исключений: адреса собственных узлов, которые обнаружение не должно блокировать |
| `meta/main.yml` | Метаданные роли |

## Структура файла tasks/main.yml

| Секция | Условие | Описание |
|---|---|---|
| Repository | Каждый запуск проверяет файлы | Обновление apt по сроку, немедленно при изменении репозитория |
| Install | По политике пакетов | Проверка dpkg audit; configure только при незавершённых операциях; одна установка движка и bouncer |
| Configuration | По фактическому содержимому | Собственный acquis.d/aiproxy.yaml и whitelist; сохранение чужих настроек |

| Apply | Только при изменении или неподтверждённом применении | Проверка конфигурации, один restart и acknowledgement |

## Ключевые механизмы

### Синхронизация коллекций

`crowdsec_hub_update_interval` по умолчанию 21600 секунд; 0 проверяет Hub на каждом
деплое. `crowdsec_hub_force_update=true` обходит срок, сохраняя проверку необходимости
применения. Политика не зависит от обновления пакетов.

При синхронизации выполняются hub update, один list, одна install для недостающих
коллекций при необходимости и upgrade --all. Сравнивается содержимое активных
правил и данных, включая зависимости. Рабочая SQLite-база с WAL/SHM исключается по пути из действующей конфигурации. Список коллекций с JSON-метаданными и новый
индекс не используются как признак необходимости рестарта.

Состояние применяется и подтверждается до выхода из роли. Прерванное применение
остаётся видимым следующему запуску, в том числе при свежем кеше. Ошибка синхронизации
не обновляет отметку успешной проверки; предусмотрены 3 попытки с задержкой 10 секунд.

Коллекции:

- **crowdsecurity/linux** -- базовые сценарии обнаружения для Linux (SSH brute-force, сканеры)
- **crowdsecurity/nginx** -- обнаружение атак на nginx (bad user-agent, path traversal, exploits)
- **crowdsecurity/http-cve** -- обнаружение эксплуатации известных CVE
- **crowdsecurity/whitelist-good-actors** -- whitelist легитимных ботов (Googlebot, Bingbot и др.)

### Acquisition config (acquis.yaml.j2)

Шаблон определяет источники логов для мониторинга:

| Источник | Условие | Тип | Описание |
|---|---|---|---|
| `/var/log/squid/access.log` | access + enable_logging | squid | Источник сохранён, но штатного разбора этой метки нет |
| `/var/log/nginx/sni-router.log` | nginx_on_443 | nginx | Поддерживаемый источник журнала маршрутизации |
| `/var/log/auth.log` | всегда | syslog | SSH brute-force, invalid users |
| journalctl `_SYSTEMD_UNIT=ssh.service` | всегда | syslog | Дублирование SSH через systemd |

Squid-логи мониторятся только на access-прокси с включённым логированием.

### Systemd memory limits

Ограничение памяти через systemd overrides (`MemoryMax`):

- CrowdSec engine: `mem_crowdsec_mb` из плана, минимум 192 МиБ
- Firewall bouncer: `mem_crowdsec_bouncer_mb` из плана, минимум 24 МиБ

### CAPI (Community API)

CrowdSec автоматически подключается к CAPI при первом запуске. Это обеспечивает:

- Получение TI-фидов от сообщества (70k+ серверов)
- Автоматический бан IP-адресов, замеченных в атаках на другие серверы
- Отправка локальных алертов в сообщество (анонимно)

## Доказательство реализации

### Конструктивное

Роль реализует полный цикл установки CrowdSec: от подключения apt-репозитория до запуска сервисов с ограничением памяти. Механизм retry при установке коллекций обеспечивает устойчивость к временным сетевым проблемам. Acquisition-конфигурация адаптируется к роли узла (access/upstream).

### Эмпирическое

- Проверка статуса сервисов: `systemctl status crowdsec crowdsec-firewall-bouncer`
- Проверка коллекций: `cscli collections list`
- Проверка CAPI: `cscli capi status`
- Проверка nftables-интеграции: `nft list ruleset | grep crowdsec`

### Негативное

- **Сбой apt-репозитория** -- `CROWDSEC_PACKAGE_DISABLE_WIZARD=1` предотвращает зависание интерактивного мастера
- **Сбой сети при установке коллекций** -- retries=3, delay=10 для hub update и collections install
- **Утечка памяти** -- systemd MemoryMax ограничивает потребление RAM
- **Broken dpkg** -- `dpkg --audit` перед установкой; configure выполняется только при обнаружении незавершённых операций
