## Описание

Ansible-роль `dns_resolver` устанавливает и настраивает кеширующий DNS-резолвер Unbound на каждой ноде инфраструктуры. Реализует каскадную архитектуру: upstream-ноды резолвят через публичные DNS, access-ноды пересылают на upstream unbound.

## Структура роли

```

├── defaults/main.yml      # Параметры по умолчанию

├── tasks/main.yml         # Основные задачи (192 строки)

```

## Параметры (defaults)

| Переменная | Значение | Описание |
|---|---|---|
| `dns_resolver_port` | 53 | Порт unbound |
| `dns_resolver_dnssec` | true | DNSSEC-валидация |
| `dns_resolver_min_ttl` | 300 | Минимальный TTL (5 мин) |
| `dns_resolver_max_ttl` | 86400 | Максимальный TTL (24 ч) |
| `dns_resolver_neg_ttl` | 60 | Negative TTL |
| `dns_resolver_prefetch` | true | Prefetch популярных записей |
| `dns_extra_clients` | `[]` | Клиенты DNS сверх группы `access_proxies` (IPv4) |

### Автовычисляемые параметры

| Параметр | Формула | Описание |
|---|---|---|
| `_dns_threads` | `max(ansible_processor_vcpus, 1)` | Потоки unbound |
| `_dns_cache_mb` | `max(предел_памяти_службы / 6, 4)` | Базовый размер кеша; msg + rrset(×2) + key дают около двух третей предела |

## Задачи (tasks/main.yml)

| # | Задача | Условие |
|---|--------|---------|
| 1 | Авторасчёт ресурсов (threads, cache) | always |
| 2 | Установка unbound + dns-root-data | Debian: apt, RHEL: dnf |
| 3 | Создание /var/lib/unbound, root.key | always |
| 4 | DNSSEC trust anchor (`unbound-anchor`) | creates |
| 5 | Allowlist клиентов `_dns_allowed_clients` | always |
| 6 | Forwarders: access → upstream unbound IPs | `proxy_role == 'access'` |
| 7 | Forwarders: upstream → публичные DNS (`dns_servers`) | `proxy_role == 'upstream'` |
| 8 | Deploy unbound.conf.j2 (с `unbound-checkconf`) | always |
| 9 | Отключение systemd-resolved stub listener | если active |
| 10 | /etc/resolv.conf → `nameserver 127.0.0.1` | always |
| 11 | Enable + start unbound | always |
| 12 | Применение отложенного перезапуска (сброс обработчиков) | always |
| 13 | Проверка слушателей с перезапуском при расхождении | always |

Задача 5 берёт готовый список `dns_allowed_clients` из `playbook.yml` ([C4-PB-001](C4-PB-001.md)) -- тот же, что получают правила firewall. Собственный расчёт по группе `access_proxies` оставлен как fallback: он нужен, только если роль вызвана из другого плейбука, где переменная не определена.

## Шаблон (unbound.conf.j2)

### Интерфейсы

| proxy_role | Интерфейсы | Доступ |
|---|---|---|
| upstream | `127.0.0.1`, `ansible_host` | localhost + access proxy IPs |
| access | `127.0.0.1` | только localhost |

### Forwarding

| proxy_role | Forwarders | Протокол |
|---|---|---|
| upstream | значения `dns_servers` из инвентори (по умолчанию 9.9.9.9, 8.8.8.8, 1.1.1.1) | plain DNS (port 53) |
| access | upstream ansible_host IPs | plain DNS (port 53) |

Обе ветки перечисляют `_dns_forwarders`, вычисленный в задачах 6--7. Ранее список для upstream был вписан в шаблон литералами, из-за чего переменная `dns_servers` не действовала: правка инвентори не меняла конфигурацию.

### Безопасность (server section)

- `hide-identity: yes`, `hide-version: yes`
- `harden-glue: yes`, `harden-dnssec-stripped: yes`
- `use-caps-for-id: yes` (0x20 encoding)
- `access-control: 127.0.0.0/8 allow` -- локальные потребители (Squid, система)
- `access-control: {клиент}/32 allow` для каждого IP из `_dns_allowed_clients` -- только на upstream
- `access-control: 0.0.0.0/0 deny` -- прочие источники; `deny` отбрасывает запрос молча, тогда как `refuse` отправлял бы ответ REFUSED, то есть отклик сканеру и плечо для отражённого трафика

Совпадение адреса ищется по самому длинному префиксу, поэтому `/32`-разрешения и `/8` для localhost сильнее общего запрета.

## Критерии приёмки

| # | Критерий | Метрика / Способ проверки | Целевое значение |
|---|----------|---------------------------|------------------|
| 1 | Роль выполняется идемпотентно | `ansible-playbook --check` | changed=0 при повторном запуске |
| 2 | unbound.conf проходит валидацию | `unbound-checkconf` (validate в template) | exit 0 |
| 3 | Unbound запущен | `systemctl is-active unbound` | active |
| 4 | resolv.conf указывает на localhost | `cat /etc/resolv.conf` | `nameserver 127.0.0.1` |
| 7 | Слушатели подняты по настроенным адресам | задача проверки в роли; на upstream — внешний адрес узла | подключение открывается |
| 5 | Allowlist в конфигурации совпадает с инвентори | `grep 'access-control' /etc/unbound/unbound.conf` | `/32 allow` на каждый IP `access_proxies`, `0.0.0.0/0 deny` |
| 6 | Forwarders upstream взяты из `dns_servers` | `grep forward-addr /etc/unbound/unbound.conf` | совпадают со значением инвентори |
