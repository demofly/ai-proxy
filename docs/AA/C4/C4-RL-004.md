## Описание

Ansible-роль `dns_resolver` устанавливает и настраивает кеширующий DNS-резолвер Unbound на каждой ноде инфраструктуры. Реализует каскадную архитектуру: upstream-ноды резолвят через публичные DNS, access-ноды пересылают на upstream unbound.

## Структура роли

```
roles/dns_resolver/
├── defaults/main.yml      # Параметры по умолчанию
├── handlers/main.yml      # Handler: Перезапустить Unbound
├── meta/main.yml          # Метаданные роли
├── tasks/main.yml         # Основные задачи (192 строки)
└── templates/
    └── unbound.conf.j2    # Шаблон конфигурации Unbound
```

## Параметры и применение

Полный набор с комментариями: [inventory.yml.sample](../../../Servers/deploy/inventory.yml.sample).
Локальный Unbound — 53; access dnsproxy — 5353; upstream DoH — общий 443 с SNI `dns.transit.internal`, backend — 8443; access
HTTP/2 Unbound — 5443; nginx TLS — 4446, наружу через общий SNI router 443.
Публичный `/q` включается `dns_doh_enabled`, обязательны `dns_doh_hostname`
и `dns_doh_acme_email`. Сертификаты каждого access автоматически сопровождает
Certbot, HTTP-01 работает через оба IP. Дополнительный сервис dnsproxy
разворачивается только на access, минимум 32 МиБ входит в общий план ресурсов.

## Задачи

| Файл | Операции |
|---|---|
| `tasks/main.yml` | Пакеты, DNSSEC anchor, ACL, forwarders и проверенный staged config |
| `tasks/doh-upstream.yml` | Проверка HTTP/2 build, самоподписанный ключ/сертификат upstream |
| `tasks/doh-bridge.yml` | Pinned dnsproxy и SHA256, локальная служба с лимитом памяти |
| `tasks/activate.yml` / `activate-bridge.yml` | Применение staged конфигов и unit после готовности upstream; реальные DNS/DoH-проверки и подтверждённые digests |
| `tasks/doh-router.yml` | Общий SNI router, частный relay, проверка конфликтов, nginx -t и откат |
| `templates/unbound.conf.j2` | Локальный DNS, DoH по роли, кеши строго по TTL зоны |
| `templates/dnsproxy.yml.j2` | Только literal HTTPS endpoints, insecure=true, без fallback/cache |
| `templates/aiproxy-doh.service.j2` | DynamicUser, sandbox systemd, GOMEMLIMIT, рестарт после отказа |

`tasks/activate.yml` вызывается из полного плейбука после firewall. Успешный
hash записывается после DNS-запроса, поэтому повторный прогон не перезапускает
Unbound при совпадении конфигурации, но восстанавливает прерванное применение.
Проверка слушателя использует loopback; реальная внешняя достижимость проверяется
DoH-запросами с access к каждому upstream. Это работает и при NAT без hairpin.

Между access и upstream используются постоянные HTTP/2-соединения поверх
**TLS 1.3**. Пул транспорта dnsproxy v0.86.0 повторно использует соединения и
закрывает их через 300 секунд без DNS-запросов; это отличается от таймаута
отдельного запроса (4 с). `tcp-idle-timeout` upstream Unbound также равен
300000 мс. После простоя следующий запрос создаёт новое TLS-соединение;
активный поток запросов не обрывается по возрасту соединения.

В Unbound 1.19 нет директивы `tls-protocols`: TLS 1.3 задаётся через отдельный
`/etc/unbound/openssl-doh.cnf` и переменную `OPENSSL_CONF` только для upstream
unbound.service. Общая политика OpenSSL узла и клиентский TLS публичного DoH
не меняются. Нативная проверка отклоняет TLS 1.2 и принимает TLS 1.3.
`tests/check_doh_idle.py` наблюдает реальное соединение более пяти минут,
проверяет сохранение до таймаута и новое соединение после него.

## Проверки

`tests/test_dns_doh.py`: настоящий Unbound HTTP/2, nginx и dnsproxy, GET/POST,

временный systemd unit, 2000 запросов под MemoryMax=32M. Состав сети и контракт:
