# C4-TM-004 -- Шаблон nftables Upstream (nftables-upstream.conf.j2)

**Последняя правка AI:** 2026-10-18

## Ссылки

- Родительские требования C3: [C3-SU-001](../C3/C3-SU-001.md)
- Связанные C4: [C4-PB-001](C4-PB-001.md) (деплоит шаблон), [C4-TM-002](C4-TM-002.md) (upstream Squid, защищаемый этим firewall)

## Описание

Файл `Servers/deploy/templates/nftables-upstream.conf.j2` (89 строк) -- Jinja2-шаблон правил межсетевого экрана nftables для upstream-узлов на Debian. Генерирует `/etc/nftables.conf`. Обеспечивает политику default drop с whitelist-доступом: SSH, Squid (только от access-прокси), DNS 53/tcp+udp (только от access-прокси), MTProxy TLS port 443 (условно, при `mtproxy_enabled`), ICMP, established/related.

## Структура файла

| Секция | Описание |
| --- | --- |
| Подготовка объектов | `add table`, создание и очистка только зарезервированных цепочек и набора; общая таблица не удаляется |
| `set dns_clients` | Клиенты DNS из inventory |
| `chain matrix_services` | Включение `/etc/shared-host/matrix-ports.nft` для соседнего Matrix |
| `chain input` | Переход в цепочку Matrix, loopback, established/related, SSH, ограниченные Squid/DNS/MTProxy и ICMP |
| `chain forward` | Политика drop |
| `chain output` | Политика accept |

## Ключевые механизмы

### Политика default drop

Базовая политика `policy drop` для цепочек input и forward. Исходящий трафик разрешён полностью (`policy accept`).

### Динамический whitelist для Squid

```
{% for host in groups['access_proxies'] %}
ip saddr {{ hostvars[host]['ansible_host'] }} tcp dport {{ squid_port }} accept
{% endfor %}
```

Правила генерируются для каждого хоста из группы `access_proxies`. При добавлении нового access-прокси в инвентори -- правило создаётся автоматически.

### Ограничение доступа к DNS-резолверу

Unbound на upstream-узле слушает внешний адрес (`ansible_host:53`), поэтому порт 53 закрывается на сетевом уровне:

```
set dns_clients {
    type ipv4_addr
    elements = { {{ dns_allowed_clients | join(', ') }} }
}
...
ip saddr @dns_clients tcp dport 53 accept
ip saddr @dns_clients udp dport 53 accept
tcp dport 53 counter drop
udp dport 53 counter drop
```

Клиенты вынесены в **именованный set**, а не в правило на каждый IP: действующий список читается одной командой `nft list set inet filter dns_clients`, а проверка источника выполняется поиском по хеш-таблице независимо от числа access-нод. Источник списка -- `dns_allowed_clients` ([C4-PB-001](C4-PB-001.md)), общий с UFW-, iptables-ветками и `access-control` в `unbound.conf` ([C4-RL-004](C4-RL-004.md)).

Явные `drop`-правила дублируют `policy drop` намеренно: они дают счётчик попыток и делают ограничение видимым в выводе `nft list ruleset` -- без них «правило не сработало» неотличимо от «правила нет».

### Набор правил input

| Приоритет | Правило | Описание |
|---|---|---|
| 1 | `ct state established,related accept` | Установленные соединения, включая ответы на исходящие DNS-запросы unbound |
| 2 | `iif "lo" accept` | Loopback: Squid резолвит через `127.0.0.1:53` |
| 3 | `tcp dport 22 accept` | SSH доступ |
| 4 | `ip saddr {access_ip} tcp dport {squid_port} accept` | Squid только от access-прокси |
| 5 | `ip saddr @dns_clients {tcp,udp} dport 53 accept` | DNS только от access-прокси (оба транспорта) |
| 6 | `{tcp,udp} dport 53 counter drop` | Явный отказ прочим источникам DNS |
| 7 | `ip saddr {access_ip} tcp dport 443 accept` | MTProxy TLS (условно, при `mtproxy_enabled`) |
| 8 | `icmp type echo-request accept` | Ping IPv4 |
| 9 | `icmpv6 type echo-request accept` | Ping IPv6 |
| default | `policy drop` | Всё остальное отбрасывается |

### Условный блок MTProxy

При `mtproxy_enabled: true` генерируются дополнительные правила, разрешающие доступ от access-прокси на порт 443 (nginx TLS relay → mtg daemon). Правила генерируются динамически аналогично Squid-блоку — для каждого хоста из `access_proxies`.

### Атомарное обновление зарезервированных объектов

Шаблон не удаляет общую `inet filter` и не вызывает `flush ruleset`. В одной
транзакции создаются недостающие и очищаются зарезервированные базовые цепочки,
дочерняя цепочка Matrix и набор DNS, затем записывается их содержимое. Чужие
цепочки и другие таблицы сохраняются. Предварительная проверка плейбука
не позволяет молча присвоить чужую непустую таблицу.

Правила Matrix включаются из отдельного файла. Его обновление выполняет helper
совместного размещения без снятия ограничений ai-proxy.

## Критерии приёмки

| # | Критерий | Метрика / Способ проверки | Целевое значение |
|---|----------|---------------------------|------------------|
| 1 | nftables запущен | `systemctl is-active nftables` | active |
| 2 | Правила загружены | `nft list ruleset` | Таблица inet filter с правилами |
| 3 | SSH доступен | Подключение по SSH | Успешно |
| 4 | Squid доступен от access | curl через Squid с IP access-прокси | 200 OK |
| 5 | Squid недоступен от стороннего IP | curl через Squid с другого IP | Connection refused / timeout |
| 6 | ICMP работает | ping upstream-хост | Ответ |
| 7 | Список клиентов DNS соответствует инвентори | `nft list set inet filter dns_clients` | Все IP группы `access_proxies` |
| 8 | DNS доступен от access (оба транспорта) | `dig @upstream example.com`, `dig +tcp @upstream example.com` | NOERROR |
| 9 | DNS недоступен от стороннего IP | `dig +time=3 +tries=1 @upstream example.com` (udp и tcp) | timeout (не REFUSED) |
| 10 | Таблица CrowdSec переживает применение конфигурации | `nft list tables` после reload | `table ip crowdsec` на месте |

## Доказательство реализации

### Конструктивное

Шаблон реализует стандартный паттерн hardened firewall: default deny с whitelist. Правила для Squid и список клиентов DNS генерируются динамически из инвентори, обеспечивая синхронизацию firewall с топологией. Атомарное обновление зарезервированных объектов сохраняет общую таблицу и чужие цепочки.

### Трассировочное

| C3 | C4 |
|---|---|
| [C3-SU-001](../C3/C3-SU-001.md) | C4-TM-004 -- firewall для upstream-узлов |

### Эмпирическое

- Проверка загрузки: `nft list ruleset` после деплоя
- Проверка доступа: curl через Squid от разных источников
- Проверка блокировки: попытка подключения на Squid-порт от стороннего IP

### Негативное

- **Несанкционированный доступ к Squid** -- policy drop + whitelist по IP
- **Открытый резолвер** -- 53/tcp и 53/udp принимаются только от `@dns_clients`, остальное отбрасывается со счётчиком; ответ не отправляется, поэтому узел не годится ни как открытый резолвер, ни как плечо отражённого трафика
- **Разрыв локального резолвинга** -- `iif "lo" accept` стоит выше запрета на порт 53, поэтому Squid и система продолжают резолвить через `127.0.0.1:53`
- **Полный lockout** -- SSH (порт 22) всегда разрешён, предотвращая потерю доступа
- **Потеря правил** -- атомарная транзакция `nft -f` с предварительной проверкой `nft -c -f`; при ошибке действуют прежние правила
- **Снятие блокировок CrowdSec** -- заменяется только `table inet filter`, таблицы bouncer'а не затрагиваются
- **IPv6-атаки** -- таблица `inet` (IPv4+IPv6) с единой политикой
