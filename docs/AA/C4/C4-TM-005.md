# C4-TM-005 — Шаблон проверки Squid для Keepalived (check_and_restart_squid.sh.j2)

## Описание

Файл `Servers/deploy/templates/check_and_restart_squid.sh.j2` — шаблон сценария оболочки, порождающий `/etc/keepalived/check_and_restart_squid.sh` с правами 0755 на access-узлах. Сценарий вызывается Keepalived как `vrrp_script check_squid` и решает две задачи разом: сообщает Keepalived о состоянии Squid и пытается поднять упавшую службу, не устраивая при этом череду перезапусков.

Разворачивается только при `proxy_role == 'access'`, включённом `enable_keepalived` и заданном `keepalived_vip`; изменение файла вызывает перезапуск Keepalived.

## Логика работы

| Шаг | Действие | Результат |
|---|---|---|
| 1 | `killall -0 squid` — проверка существования процесса сигналом 0, процесс при этом не затрагивается | Процесс жив → шаг 2; мёртв → шаг 3 |
| 2 | Удаление файла блокировки, если он остался от прошлой попытки | `exit 0` — Keepalived считает проверку пройденной |
| 3 | Чтение возраста файла блокировки `/run/keepalived_squid_restart.lock` | Возраст меньше выдержки → `exit 1` без попытки перезапуска |
| 4 | Создание файла блокировки, запись в системный журнал через `logger`, `systemctl restart squid` | `exit 1` — снижение веса узла на текущей проверке |

Ненулевой код возврата на шаге 4 намеренный: перезапуск занимает время, и объявлять узел исправным до того, как Squid поднялся, нельзя. Восстановление веса происходит на следующих проверках по параметру `rise`.

## Взаимодействие с Keepalived

Параметры заданы в [C4-TM-003](C4-TM-003.md) и определяют, как код возврата превращается в перевод виртуального адреса:

| Параметр `vrrp_script` | Значение | Смысл |
|---|---|---|
| `interval` | 2 с | Период вызова сценария |
| `weight` | −20 | Снижение приоритета узла при ненулевом коде возврата |
| `fall` | 3 | Число подряд неуспешных проверок до снижения приоритета |
| `rise` | 2 | Число подряд успешных проверок до восстановления приоритета |
| `script_user` | root | Требуется для `systemctl restart` |

Итого при полном отказе Squid приоритет снижается через 6 секунд (3 × 2 с), и виртуальный адрес переходит на второй access-узел, если его приоритет оказывается выше сниженного.

## Защита от череды перезапусков

Файл блокировки с выдержкой (`keepalived_restart_cooldown`, по умолчанию 30 с) не даёт перезапускать Squid чаще одного раза за выдержку. Без него сценарий, вызываемый каждые 2 секунды, при устойчивом отказе Squid (например, при ошибке в конфигурации) порождал бы перезапуск каждые 2 секунды, нагружая узел и заполняя журнал.

Возраст блокировки считается по времени изменения файла (`stat -c %Y`), поэтому перезагрузка узла очищает состояние вместе с каталогом `/run`.

| Переменная | Тип | Значение по умолчанию | Описание |
|---|---|---|---|
| `keepalived_restart_cooldown` | int | 30 | Минимальный промежуток между попытками перезапуска, секунды |

## Зависимости

| Зависимость | Назначение | Откуда берётся |
|---|---|---|
| `killall` | Проверка существования процесса | Пакет `psmisc`, устанавливается плейбуком |
| `systemctl` | Перезапуск службы | systemd |
| `logger` | Запись причины перезапуска в системный журнал | util-linux |

## Критерии приёмки

| # | Критерий | Метрика / Способ проверки | Целевое значение |
|---|----------|---------------------------|------------------|
| 1 | Сценарий развёрнут и исполняем | `test -x /etc/keepalived/check_and_restart_squid.sh` | код возврата 0 |
| 2 | При работающем Squid проверка проходит | запуск сценария вручную | код возврата 0, файл блокировки отсутствует |
| 3 | При остановленном Squid служба поднимается | `systemctl stop squid`, затем запуск сценария | код возврата 1, `systemctl is-active squid` → active |
| 4 | Выдержка соблюдается | два запуска подряд при остановленном Squid | второй запуск не вызывает перезапуск (запись в журнале одна) |
| 5 | Keepalived учитывает результат | `systemctl stop squid` на узле-владельце адреса | виртуальный адрес переходит на второй узел за ≤ 10 с |
